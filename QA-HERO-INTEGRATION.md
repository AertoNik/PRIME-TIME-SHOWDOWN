# Интеграция ROOK в Alpha 0.2

14 октября 2026.

## Реализация

- Найден исходный `assets/hero_base/hero_base.glb`, скопирован в `public/models/hero_base.glb`. Исходник и Blender-проект не изменены.
- `Character` по-прежнему создаёт процедурного бойца. `Arena` запускает асинхронную загрузку GLB только для игрока; после успешной подготовки скрывается прежнее тело. Противник не загружает GLB и остаётся прежним.
- `HeroVisual` использует GLTFLoader, нормализует высоту до 2,45 игровых единицы, центрирует модель и поднимает подошвы к поверхности арены. Ориентация исходника Y-up/+Z соответствует игре. Поворот к сопернику и перемещение задаёт прежний `Character.root`.
- PBR-материалы и цвета GLB сохранены, включены получение и отбрасывание теней. Параметры освещения арены не менялись; существующее низкое качество выключает динамические тени.
- Скелет: один, 32 кости. GLTFLoader удаляет точки в именах (`hand.R` → `handR`). Крепление оружия использует правую кисть; размер оружия компенсирует масштаб GLB. При отсутствии кости есть временный socket. Пистолет, дробовик и карабин остаются игровыми процедурными моделями.
- Анимационных клипов в GLB **нет**. Добавлена процедурная боевая поза и ограниченное движение костей рук/ног/корпуса. Это не авторские анимации из Blender. AnimationMixer, переключение состояний с переходом и `playClip(name)` подготовлены и проверены на отдельном тестовом клипе. Полноценные Idle/Walk/Shoot/Hit/Victory ещё нужно создать в Blender.
- Боевая симуляция, карточки, характеристики, столкновения, ИИ и сохранения не изменены. Щит, оглушение, заряд POWER SHOT и остальные эффекты остаются доступны; заряд привязан к положению оружия нового героя.
- Модель загружается один раз на страницу, переиспользуется между боями. Пока идёт загрузка и при ошибке работает процедурный герой. При уничтожении сцены освобождаются геометрия, материалы, текстуры, скелет и mixer; завершение запоздалой загрузки не добавляет объекты в уничтоженную сцену.
- Путь строится из `import.meta.env.BASE_URL`. GLB попадает в `dist/models`; CDN и новые зависимости не нужны. Three.js core, renderer и addons разделены на чанки без изменения логики base.

## Браузер

- Встроенный браузер с WebGL: ROOK отображается в меню и снаряжении, выбраны все три оружия, материалы/поворот/подошвы визуально проверены. Мобильный viewport 390×844: герой помещается в меню, интерфейс доступен.
- Ручной бой с карабином: герой перемещается, направлен на прежнего процедурного соперника, стреляет и получает урон; POWER SHOT применён, стоимость и цикл карты работают. Прогресс сохраняется после перезагрузки Vite.
- Production-preview `/PRIME-TIME-SHOWDOWN/`: меню ROOK загрузилось, на canvas `data-hero-model="glb"`. HTML, все четыре JavaScript-чанка, CSS и GLB возвращают HTTP 200; модель имеет MIME `model/gltf-binary` и совпадает с public-копией. До проверки отказа загрузки предупреждений/ошибок production в консоли не было.
- Принудительный отказ: файл временно перемещён **только в dist**, страница перезагружена. Появился прежний процедурный герой, `data-hero-model="procedural"`, бой запускался. Затем файл возвращён, идентичность public-копии подтверждена, после перезагрузки снова ROOK/`glb`. Предупреждение GLTFLoader при намеренном отказе ожидаемо; исходник и public-копия не перемещались.
- Карьера после интеграции показывает прежние данные. С ROOK в production пройден матч до результата, награды обновили фанатов с 50 до 85. PLAY AGAIN запустил следующий бой с тем же импортированным героем.
- В повторном production-матче применены POWER SHOT и SHIELD: заряд и щит видны на новом герое, результат записал обе карты и 30 блокированного урона. Возврат в меню работает.
- `git diff --check` без ошибок. Временный backup модели в dist удалён возвратом файла на исходное место; viewport возвращён к обычному размеру.

## Мобильная производительность и ограничения

Модель ~1,55 МБ, без текстур и внешних ресурсов, 33 197 треугольников, 44 skinned-примитива, 20 материалов. Пока импортирован только один герой. Скелет и материалы переиспользуются между матчами, геометрия не пересчитывается в каждом кадре. Автоматическое снижение качества и ограничение pixel ratio сохранены.

44 примитива означают дополнительные draw calls, особенно с тенями. Физические телефоны и GPU/FPS не измерялись. Для следующей оптимизации полезны объединение совместимых примитивов/материалов и LOD после проверки на целевых устройствах. Сильные сгибы требуют дальнейшей проверки весов и полноценной анимации. Опубликованный GitHub Pages не проверялся; изменения не отправлялись на GitHub.

## Проверить самостоятельно

1. `npm run dev`, открыть адрес из терминала. В меню должен стоять герой в светлой куртке с тёмными волосами.
2. В «Снаряжении» переключить пистолет/дробовик/карабин, затем войти в бой. Главный герой новый, соперник прежний. Проверить карточки, паузу, результат и PLAY AGAIN.
3. `npm run build && npm run preview` проверяет обычную локальную сборку. Для Pages используй одинаковый base при сборке и preview: `BASE_PATH=/PRIME-TIME-SHOWDOWN/ npm run build`, затем `BASE_PATH=/PRIME-TIME-SHOWDOWN/ npm run preview`; открыть `/PRIME-TIME-SHOWDOWN/`.
4. В Network запрос `models/hero_base.glb` должен завершиться HTTP 200. На canvas `data-hero-model="glb"`, `data-hero-bones="32"`, `data-hero-animations="0"`. При блокировке запроса и перезагрузке должен появиться процедурный герой, игра продолжает работать.
