# Alpha 1.9.0 — PRIME PRODUCER AVATARS: отчёт

> 30.10.2026. Локальная разработка и проверка; затем STAGING (результаты — `docs/ALPHA_1_9_0_STAGING_REPORT.md`). **На PRODUCTION и в GitHub ничего не выпущено.**

## 1. Что сделано

У игрока теперь два разных образа:

- **Продюсер** — человек за PRIME ID. Его видят в PRIME LEAGUE: в таблице, на афише, в HUD боя и в итогах.
- **Любимый боец** — по-прежнему отдельно: значок на карточке PRIME ID.

Образ продюсера — это аватар, рамка и фон. Он хранится **на сервере**, одинаков на всех устройствах и никак не влияет на бой.

| Часть | Итог |
|---|---|
| Каталог | 14 оригинальных векторных портретов, 4 рамки, 4 фона — **все бесплатные** |
| Сервер | коллекция `producer_looks`, `GET/POST /api/prime/producer`, белый список, ревизии, лимит частоты |
| PRIME ID | портрет вместо прежнего «фото», значок любимого бойца, кнопка «Настроить образ» |
| СТУДИЯ ПРОДЮСЕРА | превью, сетка аватаров, рамки, фоны; «Сохранить» и «Отмена»; объяснение для гостя |
| PRIME LEAGUE | аватары в таблице; афиша «продюсер против продюсера»; ники продюсеров в HUD; победитель на итоге — только после ответа сервера |
| Магазин | новых товаров и цен **нет** |

- **Доступ.** У каждого предмета есть `access` (`free` / `reward` / `season`). Сегодня всё `free`, и сервер принимает **только** `free`. Будущие награды можно добавить без новой схемы.
- **Образ по умолчанию.** Пока игрок ничего не выбрал, образ вычисляется из id аккаунта (FNV). Он одинаков в игре и на сервере (`defaultLook`), поэтому совпадает на всех устройствах.
- **Стиль.** Плоский вектор в палитре игры: фиолетовый, бирюзовый, розовый неон, золото. Портреты разнообразны: разные тон кожи, формы лица, причёски, одежда, аксессуары. Пол не задаётся: любой игрок выбирает любой портрет.
- **Оригинальность.** Портреты нарисованы кодом (`src/ui/producerArt.ts`): ни фотографий, ни чужих картинок, ни внешних ссылок, ни CDN. Автотест проверяет, что в 14 SVG нет `href`/`url(http`.
- **PRIME NETWORK.** У системных участников эмблема-камера, а не лицо. Они явно помечены как системные.

## 3. Сервер

- **Миграция `1793200000_prime_producer.js`.** Только добавляет коллекцию `producer_looks`:
  - поля: `owner` (уникальная ссылка на аккаунт, каскадное удаление), `avatar` / `frame` / `backdrop`, `rev`, окно лимита;
  - **без API-правил**: напрямую через `/api/collections/...` недоступна (403).
- **`lib/producer.js`:**
  - `GET /api/prime/producer` — только свой образ (вход обязателен; без выбора — образ по умолчанию);
  - `POST /api/prime/producer` — `{ avatar, frame, backdrop, rev }`:
    - только подтверждённый PRIME ID;
    - белый список из `producer_rules.js` (генерирует `npm run backend:rules`);
    - целая `rev`; если ревизия устарела → `409 look_changed` и текущий образ (не «смешанный»);
    - не больше 30 сохранений за 10 минут → `429 too_many_changes`;
    - запись в транзакции;
    - поле `owner` в запросе игнорируется — меняется только образ вошедшего аккаунта.
- **Публичный вид** — только три id (`avatar`, `frame`, `backdrop`). Без email, id аккаунта, MMR, согласий и сейва.
- **Таблица.** Образы участников читаются одним запросом (до 100 за раз).
- **Матч.** Образ соперника замораживается в снимке матча: смена образа во время боя не меняет афишу этого матча и не влияет на бой.
- **Конфигурация.** `config.producer = 1`. Отдельного флага нет, маршрут работает и при выключенной лиге (PRIME ID).

## 4. Клиент

- **`src/game/ProducerRuntime.ts`:**
  - образ вошедшего аккаунта держится **только в памяти** (не в `localStorage`);
  - при входе другого аккаунта прежний образ забывается;
  - одно сохранение за раз, с ревизией, на которой оно основано;
  - при ошибке загрузки показывается образ по умолчанию для этого аккаунта.
- **`src/ui/producerStudio.ts`** — СТУДИЯ ПРОДЮСЕРА:
  - «Сохранить» активна только при изменениях и только у подтверждённого PRIME ID;
  - понятные сообщения: «изменили в другой вкладке», «слишком много изменений», «нет связи — выбор не потерян».
- **PRIME ID (`ProfileScreen`)** — портрет 112 px, значок любимого бойца, «Настроить образ».
- **PRIME LEAGUE (`LeagueScreen`, `BattleHUD`):**
  - таблица — аватар 40 px, ник, ранг, RP;
  - афиша — два продюсера (92 px), бойцы второй строкой;
  - HUD — портреты бойцов у HP, ники продюсеров отдельно;
  - итог — «ПОБЕДИТЕЛЬ ЭФИРА» с аватаром **только после** подтверждения сервера.

## 5. Чего образ НЕ делает

- Не входит в снимок боя: в сторонах боя нет аватара, только в карточке соперника. Тот же seed и те же действия дают тот же хеш при любом образе (AV-13, на STAGING — AV-ST8).
- Не меняет `SIM_VERSION` (`76236bbb2e281ec4`), RP, MMR, жетоны, награды, характеристики бойцов и права магазина.
- Не хранится в сохранении игры: схема сейва осталась v12.
- Не продаётся: новых SKU и цен нет.
