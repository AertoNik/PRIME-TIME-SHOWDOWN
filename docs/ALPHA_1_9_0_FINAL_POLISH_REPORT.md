## 3. Античит и честность

Сервер сам знает seed, замороженные составы, арену и `SIM_VERSION`. Игра присылает только нажатия; исход, RP, токены и награды считает сервер. Подтверждено:
- 6 новых боёв через настоящий PocketBase побитово равны V8 (разные бойцы, арены, тактики, длительности, 0–21 нажатие);
- 20/20 при нагрузке;
- браузерный бой = сервер (хеш, предыдущий этап).

Ограничения остаются:
- клиент видит seed — помощь программы при игре не исключается;
- владение из карьеры — клиентское сохранение. Сила ограничена каталогом; NPC и боссы закрыты сервером;
- пересчёт в goja ≈ 1–5 с.

## 5. Нагрузка (этот Mac, `npm run league:load`)

| Сценарий | Итог |
|---|---|
| 20 `finish` подряд | min 1,2 с · медиана 2,2 с · p95 5,5 с · max 5,5 с · сервер = игра 20/20 |
| 8 `finish` одновременно | min 3,2 с · медиана 4,2 с · max 4,4 с · CPU PocketBase ≈ 600% · память 128 МБ |
| Чтения во время (health, config, таблица, профиль) | медиана 13 мс · p95 37 мс · 0 ошибок |
| Начисления | 28/28, ровно по одному |

**Вывод.** На многоядерном Mac пересчёты идут параллельно. На VPS с 1–2 vCPU 5–8 одновременных `finish` займут кратно дольше. **Нужен замер на STAGING (L14).** План при перегрузке (семафор или отдельный процесс Node) — в `ALPHA_1_9_0_STAGING_PLAN.md`, раздел 6. VPS: **NOT TESTED**.

## 6. Миграция и совместимость

- Поверх базы 1.8.9.5 (аккаунт, сохранение, история, согласие, LIVE-заказ, право): 8 таблиц лиги добавлены. Старые данные побайтно те же (отпечаток), повторный `migrate up` ничего не меняет. Откат убирает таблицы лиги, старые данные те же; повторное применение возвращает их.
- **Новый сервер + старый клиент:** старый клиент не знает лиги; все старые маршруты и ответы прежние (лишнее поле `league` в config игнорируется).
- **Новый клиент + старый сервер или флаг off:** `league.on=false` → лиги в интерфейсе нет, «В БОЙ!» — карьера.
- **Выключение флага после записей лиги:** 404 `league_off`, остальное работает (тест).
