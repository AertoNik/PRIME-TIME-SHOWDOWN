# Alpha 1.8.2 — закрытая бета на основном сайте

Основной сайт: https://aertonik.github.io/PRIME-TIME-SHOWDOWN/
Сервер: https://primetime-showdown-beta.duckdns.org (Timeweb Cloud, `invite_only`).

Почты пока нет. Тестовые аккаунты **подтверждает организатор вручную** в панели PocketBase.

---

## 1. Как работает ручное подтверждение

1. Игрок регистрируется по **действующему одноразовому приглашению**. Без кода аккаунт не создать: и в игре, и через API.
2. Игра узнаёт с сервера, что писем нет. Она **не обещает письмо**, а показывает окно «Аккаунт ожидает проверки». В PRIME ID есть кнопка «Проверить статус», кнопки «Отправить письмо» нет.
3. Пока аккаунт не подтверждён:
   - игра идёт в гостевом профиле, прогресс сохраняется на устройстве;
   - сервер отказывает в облачном сохранении (403).
4. Организатор убеждается вне игры, что email принадлежит этому человеку, и включает **verified** в панели PocketBase (раздел 4, шаг 3).
5. Игрок нажимает «Проверить статус» или входит заново. Игра предлагает перенести гостевой прогресс, после чего работает облачное сохранение.
6. «Забыли пароль?» честно отвечает, что восстановление по email временно недоступно, и ничего не отправляет.
7. Автоматического подтверждения нет. Проверка приглашений не ослаблена.

Если сервер не сообщает о почте, как сервер Timeweb сейчас, игра считает, что писем нет. Поэтому новая версия сайта работает честно и **с текущим сервером, без его обновления**.

Проверено:

- `npm run beta:test`, раздел «Без почты» — настоящий PocketBase;
- в браузере: регистрация → «ожидает проверки» → переключатель verified в панели PocketBase 0.40.5 → «Проверить статус» → перенос → «Синхронизировано».

### Обновление сервера (рекомендуется, только с вашего разрешения)

Текущий сервер при регистрации всё ещё **пытается** отправить письмо подтверждения. Попытка тихо проваливается: почтового сервера на VPS нет, и письмо никуда не уходит. Новый серверный код (`backend/pb_hooks`):

- без SMTP вообще не пытается отправлять письма;
- отвечает «почта недоступна» на служебные запросы писем;
- сообщает игре `mail:false`.

Менять `/etc/primetime/pocketbase.env` для этого **не нужно**.

Как обновить, когда разрешите:

1. На Mac: `npm run server:bundle`.
2. Загрузите архив в новую папку на сервере.
3. Выполните `sudo bash deploy/linux/update.sh` (см. [PRIME_CLOUD_DEPLOY.md](PRIME_CLOUD_DEPLOY.md), шаг 10). Скрипт сначала сам делает копию базы.

Проверка после обновления:

```bash
curl https://primetime-showdown-beta.duckdns.org/api/prime/config
```

В ответе должно быть `"mail":false,"verification":"manual"`.

## 2. Почему сайт станет бетой, а обычная сборка — нет

GitHub Actions в папке публикации выполняет `npm ci` и `npm run build`. Сборка читает файл **`.env.production`**. Команда `npm run publish:sync` создаёт этот файл в папке публикации из вашего `.env.beta`. В нём ровно две строки:

```
VITE_PRIME_ACCOUNTS=beta
VITE_PRIME_API_URL=https://primetime-showdown-beta.duckdns.org
```

Это публичные значения, без паролей и ключей. В рабочей папке `.env.production` нет, поэтому `npm run build` здесь по-прежнему собирает гостевую игру без аккаунтов. `npm run accounts` проверяет обе сборки во временных папках, независимо от того, что лежит в `dist/`.

`vite.config.ts` (`base: './'`) и `deploy.yml` не менялись.

## 3. Публикация — по шагам

### Шаг 1. Проверки в рабочей папке (Терминал, папка `PRIME TIME Duel`)

```bash
npm run build && npm run accounts && npm run beta:test
```

Должно быть:

- `accounts: OK` — обе сборки проверены;
- `beta: OK`.

### Шаг 2. Точка отката (Терминал, папка публикации)

Сейчас опубликована версия из последнего коммита папки публикации («Обновление 1.8»). Отметьте её тегом, чтобы легко вернуться:

```bash
git -C ~/Desktop/"PRIME TIME SHOWDOWN" tag before-1.8.2-beta
```

Тег локальный, ничего не публикует.

### Шаг 3. Пробный перенос (ничего не меняет)

```bash
npm run publish:sync -- ~/Desktop/"PRIME TIME SHOWDOWN"
```

Команда покажет:

- какие файлы новые или изменились;
- что `.env.production` будет создан;
- что `deploy.yml` не трогается;
- нет ли в файлах проекта чего-то похожего на секреты. Если есть, она остановится.

### Шаг 4. Перенос

```bash
npm run publish:sync -- ~/Desktop/"PRIME TIME SHOWDOWN" --apply
```

Команда копирует **только файлы проекта**, включая скрытые `.gitignore` и `.env.example`, которые Finder пропускает. Никогда не копируются:

- `backend/pb_data`, `backend/bin`, `backend/backups`;
- `backups-private`, `server-bundle`;
- `node_modules`, `dist`;
- настоящие `.env`.

Ничего не удаляется. В конце команда спрашивает у git, что он собирается закоммитить, и громко останавливается, если видит базу, копии или ключи.

Не копируйте папки вручную через Finder. Он пропускает файлы с точкой в начале, например `.gitignore`.

### Шаг 5. Коммит (VS Code, папка публикации)

Source Control → посмотрите список. В нём должны быть:

- `.env.production`, `.gitignore`;
- изменения в `src/`, `backend/pb_hooks`, `backend/pb_migrations`, `backend/pb_public`, `deploy/linux`, `docs/`, `scripts/`;
- `package.json`, `package-lock.json`, `index.html`, `README.md`.

**Не должно быть:** `pb_data`, `bin`, `backups`, `backups-private`, `server-bundle`, `node_modules`, `dist`, файлов `.db`, `.zip`, `.age`.

Сделайте **один коммит**, например «Alpha 1.8.2 closed beta», затем Sync.

### Шаг 6. Проверка публикации

1. GitHub → репозиторий → **Actions**: сборка «Deploy…» должна стать зелёной (обычно 1–3 минуты).
2. Откройте сайт и обновите страницу. Внизу заставки должно быть **ALPHA 1.8.2 · CLOSED BETA**.
3. PRIME ID → блок PRIME NETWORK со значком **CLOSED BETA** и кнопкой «Есть приглашение — создать аккаунт». Если там «Сервер PRIME NETWORK сейчас недоступен», проверьте:
   - `healthcheck` на сервере;
   - что `PRIME_ORIGINS=https://aertonik.github.io`.

### Откат сайта

В папке публикации отмените коммит беты и выполните Sync:

```bash
git -C ~/Desktop/"PRIME TIME SHOWDOWN" revert --no-edit HEAD
```

GitHub Actions соберёт прежнюю версию. Это **откат только сайта**:

- база PocketBase не откатывается — созданные аккаунты и облачные сохранения остаются на сервере;
- гостевой прогресс игроков в браузере не трогается;
- прогресс в аккаунтах сохраняется на сервере и вернётся при повторной публикации беты.

Базу сервера восстанавливают отдельно, только из резервной копии ([PRIME_CLOUD_BACKUP.md](PRIME_CLOUD_BACKUP.md)).

## 4. Первый настоящий тест

**1. Новый код, старый отозвать.** На сервере через SSH:

```bash
sudo /opt/primetime/deploy/invites.sh list
sudo /opt/primetime/deploy/invites.sh revoke <id или сам код с того скриншота>
sudo /opt/primetime/deploy/invites.sh create 1 days=7 note=первый-тест
```

В `list` старый код узнаётся по последним 4 символам (колонка «конец»). Новый код скопируйте в личные заметки и **не делайте скриншот**. После `revoke` можно выполнить `invites.sh stats`: отозванных должно стать на 1 больше.

**2. Тестовый PRIME ID.** На Mac откройте сайт → PRIME ID → «Есть приглашение — создать аккаунт». Заполните ник, свой email, пароль и код, затем «Создать аккаунт». Появится окно «Аккаунт ожидает проверки».

**3. Ручное подтверждение.**

1. На Mac в отдельной вкладке Терминала откройте туннель и не закрывайте его:

   ```bash
   ssh -N -L 18090:127.0.0.1:8090 root@IP-СЕРВЕРА
   ```

2. Откройте http://127.0.0.1:18090/_/ и войдите как суперпользователь.
3. Перейдите в **Collections → users**, найдите строку с email и откройте её.
4. Включите переключатель **verified**. В вопросе *Do you really want to manually change the verified account state…* нажмите **Yes, verify**, затем **Save changes**. В списке появится `verified: True`.
5. Закройте туннель: Ctrl+C.

Для друзей сначала убедитесь, что адрес их:

1. `invites.sh list all` покажет, какое приглашение (по пометке `note`) использовано.
2. В панели (**Collections → invites** → поле **usedBy**) видно, какой аккаунт его использовал.
3. Уточните у друга в личном сообщении, какой email он указал, и только после совпадения включайте verified.

**4. Вход.** В игре нажмите «Проверить статус» в окне или в PRIME ID. Можно также «Выйти» и «Войти» заново.

**5. Перенос гостевого прогресса.** Появится окно «Перенести прогресс в PRIME ID?» → «Перенести прогресс». Игра перезапустится в аккаунте, в PRIME ID будет «Синхронизировано · время».

**6. Другое устройство.**

1. Откройте сайт в другом браузере или в Safari на iPhone → PRIME ID → «Войти» тем же email и паролем. Должна загрузиться та же карьера.
2. Сыграйте матч на одном устройстве и откройте игру на другом: она предложит загрузить новый прогресс из аккаунта.

**7. Гостевой режим и прежние сохранения.**

- В приватном окне браузера сайт работает как гостевая игра: можно играть, аккаунт не нужен.
- На первом браузере PRIME ID → «Выйти» → игра вернётся к гостевому профилю, и прежний гостевой прогресс на месте. При переносе он копируется, а не удаляется.

Если что-то пошло не так, запишите, что видно на экране (без кодов и паролей). Журнал сервера: `sudo journalctl -u pocketbase -n 100 --no-pager`.

## 5. Что пока не работает (честно)

- Нет восстановления пароля по email. Если тестировщик забыл пароль, организатор может задать новый в панели (переключатель «change password» в записи пользователя) и передать его лично. В игре сменить пароль пока нельзя.
- Нет смены email.
- Подтверждение только вручную.
- Страницы локального предпросмотра (`localhost`) к серверу не подключатся: сервер разрешает только `https://aertonik.github.io`. Так и задумано.
- На iPhone с настоящим сервером я не проверял — это шаг 6 первого теста.
