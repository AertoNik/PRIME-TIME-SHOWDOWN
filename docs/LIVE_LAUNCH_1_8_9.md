# PRIME SHOP — запуск настоящих продаж для всех PRIME ID (Alpha 1.8.9)

> Подготовлено локально 28.10.2026. Ничего не развёрнуто. Каждый шаг ниже — только с разрешения владельца.

## 1. Что открывает настоящую продажу

Настоящий заказ создаётся, только если выполнены **все** условия:

| Где | Настройка | Значение для LIVE |
|---|---|---|
| код игры и сервера | `SHOP_SALES_OPEN` → `salesOpen` в `shop_rules.js` (`npm run backend:rules`) | `true` (этот релиз может продавать) |
| сервер | `PRIME_SERVER_ROLE` | `production` (LIVE в другой роли отключается: `live_outside_production`) |
| сервер | `PRIME_PAY_MODE` | `live` |
| сервер, `/etc/primetime/robokassa.env` | `ROBOKASSA_MERCHANT_LOGIN`, `ROBOKASSA_HASH_ALGORITHM=sha256`, `ROBOKASSA_PASSWORD_1`, `ROBOKASSA_PASSWORD_2` | боевые; **тестовых паролей в файле быть не должно** (`test_secrets_on_live_server`) |
| сервер | `ROBOKASSA_RECEIPT` | `on` (без него — `receipt_required_for_live`, игра показывает «не в продаже») |
| сервер | `PRIME_SHOP_SALES` | `open` — **аварийный выключатель** |

Чего-то не хватает → оплата выключена (причина видна в `pocketbase prime-shop status` и в журнале запуска). Белых списков нет: покупать может любой PRIME ID с подтверждённым email, принятыми документами, отметкой «18+» и принятой офертой (редакция 2).

Покупатель с отметкой «13-17» получает отказ `adult_only` — так требует оферта (раздел 5.1). Правила регистрации и возрастной порог не менялись.

## 2. Порядок DEMO → LIVE

1. **Резервная копия.** Свежая копия production (`backup.sh`), затем `backup-check.sh`: в копии должен быть `prime-ledger`.
2. **Сервер.** Архив `server-bundle/prime-server-1.8.9-alpha-live-<sha>.tar.gz` через `update.sh`. Миграций нет: меняются 5 файлов хуков. DEMO продолжает работать как раньше.
3. **Клиент.** `publish:sync --apply`, commit и push. GitHub Actions соберёт сайт. Пока сервер в DEMO, игра показывает демо-оплату, как сейчас.
4. **Переключение** — одним изменением и одним перезапуском:
   * `/etc/primetime/robokassa.env`: убрать `ROBOKASSA_TEST_PASSWORD_1/2`, вписать `ROBOKASSA_PASSWORD_1/2` (боевые), `ROBOKASSA_RECEIPT=on`. Логин и `sha256` оставить.
   * `/etc/primetime/pocketbase.env`: `PRIME_PAY_MODE=live`, `PRIME_SHOP_SALES=open`, добавить `PRIME_PAY_RELAY_PUBLIC_URL=https://primetime-showdown-staging.duckdns.org`. `PRIME_DEMO_UNTIL` в LIVE не читается, его можно оставить.
   * `sudo systemctl restart pocketbase` и `pocketbase prime-shop status`. Ожидается: `mode: live`, `ready: true`, `algorithm: sha256`, `receipt: on (НПД…)`, `ledger: ok`.
5. **Контрольная покупка владельцем** самого дешёвого предмета (49 ₽). Проверить:
   * на странице Robokassa: «Состав заказа» (название, 49 ₽), нет надписей о тесте;
   * после оплаты: `prime-shop order <InvId>` — `fulfilled`, право `live`; предмет в коллекции; после повторного входа предмет на месте;
   * чек НПД — по разделу 4.
6. **Демонстрация.** В LIVE учитываются только live-права, поэтому демо-предметы у игроков пропадают из коллекции (оферта, раздел 12: это не покупка). Записи о них не удаляются. `prime-shop demo-end` — необязательная пометка демо-прав как отозванных (история сохраняется). Запускать только по отдельному решению, после контрольной покупки.

## 3. Аварийное закрытие

`PRIME_SHOP_SALES=closed` в `/etc/primetime/pocketbase.env` → `sudo systemctl restart pocketbase`. Нового релиза не нужно.

* Новые заказы и платёжные страницы не выдаются (`sales_closed`), игра показывает «Продажи пока не открыты».
* Созданные заказы сохраняются. Подписанный ResultURL по ним подтверждается, предмет выдаётся.
* Права игроков, возвраты (`prime-shop refund …`), журнал счетов и сверка продолжают работать.
* Пока сервер перезапускается (несколько секунд), Robokassa повторяет уведомления сама.

**Не использовать как выключатель** `PRIME_PAY_MODE=off` и не удалять пароли: тогда сервер отвечает на ResultURL кодом 503, и подтверждения уже оплаченных заказов ждут, пока оплата не будет включена снова.

## 4. Проверка чека НПД после контрольной оплаты

В «Мой налог» → «Чеки», и в письме покупателю:

- [ ] **название** = название заказа: «Цифровой предмет оформления … для игры PRIME TIME: SHOWDOWN»;
- [ ] **сумма** = сумма оплаты (49 ₽), одна позиция;
- [ ] **время** = время оплаты в Robokassa (с точностью до минут);
- [ ] **продавец** — ваше ФИО и ИНН, статус «действителен»;
- [ ] **покупатель** — физическое лицо; чек пришёл на email, указанный на странице Robokassa;
- [ ] номер счёта и сумма совпадают с `prime-shop order <InvId>` и с операцией в кабинете Robokassa.

Пока все пункты не выполнены, приём чеков не считается подтверждённым.

## 5. Возврат за настоящую покупку

1. Деньги вернуть в кабинете Robokassa.
2. `pocketbase prime-shop refund <InvId> reason="…"` → `refund-done <InvId>`: право отзывается, история сохраняется.
3. **Чек НПД:** аннулировать чек в «Мой налог» с причиной «Возврат средств». Сервер этого не делает, и автоматическое аннулирование «Робочеками СМЗ» не подтверждено.

## 6. Восстановление из копии после начала продаж

Не восстанавливать старую базу вручную. Только `restore.sh`: он **сливает** журнал счетов (`prime-ledger`). Номера счетов не повторяются, а оплаты и возвраты, сделанные после копии, восстанавливаются из журнала при первом запуске (`npm run payments`, раздел «Восстановление старой копии»).
