## 4. Порядок выпуска (следующий этап, не сейчас)

1. **Решения владельца:**
   - баланс (`docs/PRIME_LEAGUE_BALANCE.md`; STAGING шёл с вариантом C);
   - включать ли PRIME TOKENS;
   - дата сезона 1;
   - отчёт STAGING.
2. **Резервная копия PRODUCTION** прямо перед выпуском: `backup.sh` → `backup-check.sh`.
3. **Сервер PRODUCTION:**
   - загрузить архив, `sha256sum -c`;
   - `sudo bash deploy/linux/update.sh` (`PRIME_INSTANCE` по умолчанию `production`);
   - флаги лиги **не включать**.
4. **Проверки после сервера** (только чтение):
   - health; `prime-shop status` (live, ready, receipt on, ledger ok);
   - аккаунты, заказы и права до и после — совпадают;
   - `/api/prime/config`: `league.on=false`, `producer=1`;
   - `/api/prime/league/me` → 404 `league_off`;
   - вход владельца, PRIME ID: образ по умолчанию, студия сохраняет.
5. **Клиент:**
   - `npm run publish:sync` — сначала пробный прогон, проверить diff, затем `--apply`;
   - коммит, push, зелёный GitHub Actions.
   - На сайте: ALPHA 1.9.0; «В БОЙ!» → карьера; PRIME ID → «Настроить образ».
6. **Включение лиги — отдельным решением:**
   - `PRIME_LEAGUE=on`, по решению `PRIME_LEAGUE_TOKENS=on`, `PRIME_LEAGUE_SEASON_START=<день запуска>`, `PRIME_LEAGUE_UPGRADES` пусто;
   - перезапуск;
   - короткая проверка на аккаунте владельца: вступить, защита, одна дуэль. В журнале не должно быть `replay differ`.

## 5. Наблюдение после включения

- **Журнал.** `prime league: the game and the server replay differ` должен отсутствовать. Любая такая запись — повод выключить лигу и разобраться.
- **`finish`.** Время ответа и CPU процесса. На STAGING замеры этого VPS — в отчёте STAGING, раздел L14.
- **Просроченные матчи.** `league_matches` в статусе `active` старше срока: cron (каждые 2 мин) должен их закрывать.
- **Лимит частоты.** На `/api/prime/` действует 60 запросов в минуту с одного IP. Лига делится им с сохранениями, DAILY и магазином. Игроки за одним IP (мобильный оператор, одна квартира) делят лимит. При жалобах на 429 — отдельный лимит для `/api/prime/league/` (решение владельца).

## 6. Откат (никакого отката базы)

- **Лига мешает:** `PRIME_LEAGUE=` и перезапуск. Карьера, магазин, PRIME CLOUD и образ продюсера работают как раньше. Данные лиги остаются.
- **Сервер:** `update.sh` с проверенным архивом 1.8.9.5 (`8cb5e402…`).
  - Коллекции лиги и `producer_looks` остаются: старый сервер их не трогает.
  - **Миграции и образы не удалять**, если в них уже есть данные.
- **Клиент:** `git revert` коммита 1.9.0 в папке публикации — только как план; без отдельного решения не выполнять.
- **STAGING при аварии:** `update.sh` с предыдущим проверенным архивом и резервной копией из `/var/backups/primetime-staging/` (данные и копии сохраняются).
