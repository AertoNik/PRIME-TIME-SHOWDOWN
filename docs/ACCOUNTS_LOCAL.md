# Как запустить локальные аккаунты PRIME ID на Mac (Alpha 1.8.1 – 1.8.2)

Это **локальный тест** аккаунтов. Всё работает только на вашем Mac:

- сервер аккаунтов PocketBase слушает `127.0.0.1:8090`;
- тестовая почта Mailpit — `127.0.0.1:8025`;
- игра с аккаунтами запускается командой `npm run dev:accounts`.

Из интернета или с других устройств в Wi-Fi до сервера не достучаться, настоящие письма никуда не уходят. Опубликованная игра на GitHub Pages аккаунтов не содержит и ни к какому серверу не обращается.

**С Alpha 1.8.2 локальный сервер по умолчанию работает как закрытая бета:** новый аккаунт создаётся только с кодом приглашения (`npm run invites -- create 1`, шаг 8). Существующие аккаунты входят как раньше. Подготовка настоящего сервера описана в [PRIME_CLOUD_PREDEPLOY.md](PRIME_CLOUD_PREDEPLOY.md).

Все команды ниже выполняются в Терминале **из папки проекта**:

```bash
cd ~/Desktop/"PRIME TIME Duel"
```

Если `npm` не находится, сначала подключите Node (он уже установлен через nvm):

```bash
source ~/.nvm/nvm.sh
```

## 1. Где находится PocketBase

| Что | Где |
|---|---|
| Программы PocketBase 0.40.5 и Mailpit 1.31.6 | `backend/bin/` (в git не попадают) |
| Миграции базы — коллекции, правила доступа, почта, лимиты | `backend/pb_migrations/` |
| Серверный код (регистрация, приглашения, облачные сохранения, защита почты) | `backend/pb_hooks/` |
| Страницы из писем (подтверждение email, новый пароль) | `backend/pb_public/auth/` |
| Ваша локальная база (аккаунты, сохранения) | `backend/pb_data/` (в git не попадает) |
| Резервные копии базы | `backend/backups/` (в git не попадают) |
| Копия базы перед 1.8.2 | `backups-private/` (в git не попадает) |
| Версии и контрольные суммы скачиваемых программ | `backend/versions.json` |
| Скрипты запуска и остановки | `scripts/backend.ts` → команды `npm run backend…` |

## 2. Установка (если `backend/bin` пустая)

На этом Mac программы уже установлены. На другом компьютере или после удаления папки:

```bash
npm run backend:install
```

Скрипт скачивает **только официальные** архивы с GitHub (pocketbase/pocketbase и axllent/mailpit) для вашего процессора (Intel или Apple Silicon). Каждый файл сверяется с SHA-256 из `backend/versions.json`; при несовпадении он удаляется и ничего не запускается. Нужен интернет и `/usr/bin/curl`, который есть в macOS.

Проверить, что установлено:

```bash
npm run backend:status
```

## 3. Локальный суперпользователь (администратор PocketBase)

Это ваш личный вход в панель PocketBase. В игре он не используется и ни в какие файлы проекта не записывается.

1. Запустите backend (шаг 4).
2. При **самом первом** запуске PocketBase выведет в терминал ссылку вида `http://127.0.0.1:8090/_/#/pbinstall/…` и подсказку `>>> Первый запуск…`.
3. Откройте ссылку в браузере и задайте **свой** email и пароль администратора. Пароль игроков и пароль из этой инструкции использовать не нужно — придумайте отдельный.

Если ссылка потерялась, суперпользователя можно создать командой (пароль останется в истории терминала):

```bash
./backend/bin/pocketbase superuser upsert ВАШ_EMAIL ВАШ_ПАРОЛЬ --dir backend/pb_data
```

## 4. Запустить backend

Откройте **первую вкладку** Терминала:

```bash
npm run backend
```

Запускаются PocketBase и Mailpit, при первом запуске применяются миграции базы (в 1.8.2 — добавляется коллекция `invites`; аккаунты и сохранения не меняются, это проверено на копии вашей базы). В терминале появится сводка с адресами и режимом регистрации. Пока окно открыто, backend работает.

Режим регистрации на Mac:

| Команда | Регистрация |
|---|---|
| `npm run backend` | по приглашениям (закрытая бета) — по умолчанию |
| `npm run backend -- --registration disabled` | закрыта, только вход |
| `npm run backend -- --registration public` | без кода (как в 1.8.1) — только для локальных опытов |

## 5. Панель администратора

`http://127.0.0.1:8090/_/` — войдите как суперпользователь. В панели видны:

- коллекции `users`, `profiles`, `saves`, `save_history`, `invites` (только хеши кодов — самих кодов там нет);
- логи;
- настройки (Settings → Mail settings, Rate limits, Backups).

Схему коллекций в панели лучше не менять: она задаётся миграциями. Автогенерация миграций выключена, поэтому ручные правки в панели не сохранятся в проекте.

## 6. Тестовая почта

Настраивать ничего не нужно: миграция направляет все письма в Mailpit на `127.0.0.1:1025`. Дополнительно серверный хук блокирует отправку на любой другой SMTP-сервер. Письма видны на `http://127.0.0.1:8025/`. Они временные и исчезают после остановки backend.

## 7. Запустить игру с аккаунтами

Откройте **вторую вкладку** Терминала:

```bash
npm run dev:accounts
```

Откройте **ровно тот адрес, который Vite напечатает в строке `Local:`** — обычно `http://localhost:5173/`. Если порт 5173 занят (например, уже открыт другой `npm run dev`), Vite сам возьмёт 5174, 5175… — это нормально: backend принимает запросы со страниц на портах 5173–5180. Обычный `npm run dev` — та же игра **без** аккаунтов, как в Alpha 1.8; в PRIME ID она прямо об этом пишет.

Файл `.env.accounts` необязателен: режим `npm run dev:accounts` сам включает аккаунты с адресом `http://127.0.0.1:8090`. (Finder не показывает и часто не копирует файлы с точкой в начале имени — из-за этого в скопированной папке блок PRIME NETWORK раньше пропадал.)

Если кнопок регистрации и входа нет, PRIME ID показывает причину: игра запущена без аккаунтов, backend не отвечает или отвечает, но не принимает запросы с этой страницы. Подробности — одной строкой в консоли браузера (`[PRIME NETWORK] …`).

## 8. Зарегистрировать первый аккаунт

1. Создайте код приглашения (в третьей вкладке Терминала, backend можно не останавливать):

   ```bash
   npm run invites -- create 1
   ```

   Код вида `PT-XXXXX-…` показывается **один раз** — скопируйте его. Другие команды (список, отзыв, срок) — [PRIME_CLOUD_INVITES.md](PRIME_CLOUD_INVITES.md).
2. Главное меню → бейдж уровня (с меткой ID) → **PRIME ID**.
3. В блоке **PRIME NETWORK · CLOSED BETA · ЛОКАЛЬНО** нажмите **«Есть приглашение — создать аккаунт»**.
4. Заполните поля:
   - **никнейм** — 3–16 символов: буквы одного алфавита (латиница *или* кириллица), цифры, «_»;
   - **email** — любой тестовый, например `you@prime.test`;
   - **пароль** — от 8 символов, обязательно буквы и цифры;
   - **повтор пароля**;
   - **код приглашения** — можно вставить целиком, регистр и пробелы не важны.
5. После отправки появится окно «Подтвердите email». Игра пока продолжается в гостевом профиле.

Если backend не запущен, PRIME ID покажет «Локальный сервер аккаунтов не отвечает» и кнопку «Проверить снова».

## 9. Где увидеть письмо

Откройте `http://127.0.0.1:8025/` — там письмо «PRIME TIME: SHOWDOWN — подтвердите email». В окне игры тоже есть ссылка на тестовую почту.

## 10. Подтвердить email

1. В письме нажмите **«Подтвердить email»**. Откроется страница PRIME NETWORK «Email подтверждён» с кнопкой возврата в игру.
2. Вернитесь в игру и нажмите **«Я подтвердил»**.

Ссылка действует 24 часа. Повторно её открывать не страшно. Новое письмо — кнопка «Отправить письмо ещё раз».

## 11. Перенести гостевое сохранение

Если в этом браузере уже есть гостевая карьера, после подтверждения появится окно **«Перенести прогресс в PRIME ID?»** с кратким описанием карьеры. Действия:

- **«Перенести прогресс»** — в аккаунт уходит вся карьера:
  - бойцы и колоды, купленные карты;
  - коллекция и титулы;
  - Halloween-жетоны и задания, LUCIEN;
  - рекорды режимов, серии побед.

  Звук, музыка, графика и камера остаются настройками устройства. Игра перезапустится уже в аккаунте. Гостевая карьера остаётся в браузере резервной копией и второму аккаунту автоматически не предлагается.
- **«Начать новую карьеру»** — аккаунт начинает с нуля, гостевая карьера остаётся на устройстве.
- **«Решить позже»** — ничего не меняется.

В PRIME ID появятся ваш никнейм, статус **АККАУНТ** и строка синхронизации.

## 12. Второй тестовый аккаунт

1. PRIME ID → **«Выйти»**. Игра вернётся к гостевому профилю.
2. Новый код (`npm run invites -- create 1`) → **«Есть приглашение — создать аккаунт»** → другой никнейм и email → подтвердите письмо.
3. Новый аккаунт начинает свою карьеру. У каждого аккаунта свой локальный слот: деньги, бойцы, LUCIEN, колоды и коллекция не смешиваются.

## 13. Синхронизация между браузерами

> **С Alpha 1.8.3 (PRIME CLOUD 2.0)** локальный backend, как и сервер, разрешает одну активную игру на аккаунт: открыли аккаунт во втором браузере — играет он, первый показывает «PRIME ID ОТКРЫТ НА ДРУГОМ УСТРОЙСТВЕ» и «Продолжить здесь»; прогресс загружается сам, окна «Обнаружены два сохранения» в обычном случае больше нет. Правила 1.8.2 (описанные ниже) включаются только выключателем: `PRIME_SESSIONS=off npm run backend`. Подробно — [PRIME_CLOUD_2_DEPLOY.md](PRIME_CLOUD_2_DEPLOY.md), раздел 1.

Адреса `http://localhost:5173` и `http://127.0.0.1:5173` для браузера — разные сайты со своим хранилищем. Это удобная замена второму устройству. Также подойдёт другой браузер, например Safari вместо Chrome, на адресе `http://localhost:5173`.

1. В первом браузере войдите в аккаунт и сыграйте матч. Через несколько секунд статус станет «Синхронизировано».
2. Во втором браузере: PRIME ID → «Войти» тем же email. Загрузится та же карьера.
3. Сыграйте на одном и откройте другой. Он увидит новый прогресс и предложит «Загрузить из аккаунта», а на заставке загрузит его сам.
4. Если прогресс изменить в обоих браузерах, появится окно **«Обнаружены два сохранения»** с действиями:
   - **«Использовать облако»**;
   - **«Использовать это устройство»**;
   - **«Решить позже»**.

   Вторая версия сохранится в **облачных копиях** — кнопка «Облачные копии» в PRIME ID, до 10 версий, восстановление с подтверждением.

Без сервера игра работает как обычно: статус «Нет подключения · изменения ждут отправки». После запуска backend изменения отправятся сами или по кнопке «Синхронизировать».

## 14. Остановить backend

В вкладке, где идёт `npm run backend`, нажмите **Ctrl+C**. Если вкладку закрыли:

```bash
npm run backend:stop
```

Игру (`npm run dev:accounts`) останавливают так же — Ctrl+C в её вкладке.

## 15. Запустить снова без потери тестовой базы

```bash
npm run backend
```

База лежит в `backend/pb_data` и не удаляется при остановке. Аккаунты, сохранения и суперпользователь остаются. Письма Mailpit временные. Сессия в игре действует 7 дней и продлевается при каждом запуске игры; если она истекла, PRIME ID предложит «Войти снова» — прогресс при этом не теряется.

## 16. Резервная копия локальной базы

**Способ А — backend запущен:** панель `http://127.0.0.1:8090/_/` → Settings → Backups → создать новую копию. Архив сохранится в `backend/pb_data/backups`.

**Способ Б — команда (с 1.8.2 работает и при запущенном backend):**

```bash
npm run backend:backup
```

Копия сохранится в `backend/backups/pb_data-ДАТА/` и `.zip`; она сделана встроенным онлайн-копированием SQLite и проверена на целостность.

**Восстановление** и проверка новых миграций на копии (`npm run backend:migrate-check`) — [PRIME_CLOUD_BACKUP.md](PRIME_CLOUD_BACKUP.md), раздел 1.

Копия лежит на том же диске. От поломки или потери Mac она не спасает — для важных данных храните копию ещё и отдельно.

## Проверки для разработчика

```bash
npm run accounts
```

Проверки без сервера, несколько секунд: правила форм и сервера, конфликты, копия сохранения, отсутствие аккаунтов в production-сборке. Сначала выполните `npm run build`.

```bash
npm run backend:test
```

Настоящий PocketBase и Mailpit на запасных портах (18190 / 11125 / 18125; порт 18090 оставлен для SSH-туннеля к серверу), с временной базой, которая удаляется в конце. Ваша `backend/pb_data` не затрагивается. Нужен `npm run backend:install`.

```bash
npm run beta:test
```

1.8.2: закрытая бета на настоящем PocketBase (порты 18590 / 11525 / 18525, временная база) — режимы регистрации, сценарии приглашений, обход через API, лимиты, плохое соединение, копии и восстановление, перенос базы с ключом шифрования, удаление аккаунта.

Если менялись бойцы, карты, предметы, павильоны или схема сохранения, выполните

```bash
npm run backend:rules
```

и перезапустите backend.

## Телефон в той же Wi-Fi сети

Не поддерживается, и это сделано намеренно. Сервер слушает только `127.0.0.1`, а игра включает аккаунты только на странице, открытой с этого же компьютера. С телефона PRIME NETWORK просто не показывается, гостевая игра работает. Проверка на телефоне — после Stage 2, с настоящим HTTPS-сервером.

Временный вариант через Wi-Fi (PocketBase на `0.0.0.0` и разрешение адреса локальной сети в игре) открыл бы тестовую базу всем устройствам сети без шифрования. Его стоит делать только по отдельному решению.

## Что сознательно не входит в локальный тест

- Публичная регистрация на сервере (локально — только по флагу `--registration public`).
- Настоящая почта.
- HTTPS и домен — это Stage 2 ([PRIME_CLOUD_DEPLOY.md](PRIME_CLOUD_DEPLOY.md)).
- Мировой рейтинг, PvP, магазин.

Античит ограничен базовыми проверками: бои по-прежнему считаются в браузере, поэтому деньги и победы из сохранения не являются доказательством.
