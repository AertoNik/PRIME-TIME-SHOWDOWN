# PRIME CLOUD — приглашения закрытой беты

В закрытой бете аккаунт создаётся только с **кодом приглашения**. Коды выдаёт разработчик. Создать код можно только командой на самом сервере или на Mac. Ни игра, ни открытый адрес в интернете этого не умеют.

## Как выглядит код

```
PT-XXXXX-XXXXX-XXXXX-XXXXX-XXXXXX
```

- 26 случайных символов (130 бит), генератор криптографический.
- В коде нет похожих букв: при вводе `O` читается как `0`, `I` и `L` — как `1`. Регистр, пробелы и дефисы не важны. Код можно вставить целиком, как он пришёл в сообщении.
- В базе хранится **только хеш** кода (SHA-256). Код показывается один раз, при создании. Потерянный код не восстановить: отзовите его и создайте новый.
- По умолчанию код одноразовый и действует **14 дней**.
- Проверка кода и создание аккаунта идут в одной транзакции базы. Если двое одновременно введут один код, аккаунт получит только один.
- Через обычный API PocketBase приглашения нельзя ни прочитать, ни создать, ни изменить. Регистрация в обход кода закрыта. Это проверяет `npm run beta:test`.

## Команды на Mac (локальный тест)

Backend можно не останавливать.

```bash
npm run invites -- create 1                       # один код на 14 дней
npm run invites -- create 5 --days 7              # пять кодов на 7 дней
npm run invites -- create 1 --note "Саша"         # с пометкой для себя
npm run invites -- create 1 --days 0              # без срока действия
npm run invites -- create 1 --uses 3              # один код на 3 аккаунта
npm run invites -- list                           # активные приглашения
npm run invites -- list all                       # все: использованные, истёкшие, отозванные
npm run invites -- stats                          # сколько свободных / использованных / …
npm run invites -- revoke <id или сам код>        # отозвать
```

Ограничения: до 100 кодов за раз, срок до 365 дней, до 100 использований на код.

Если команда пишет «Коллекции invites ещё нет», запустите один раз `npm run backend`: при запуске применяется миграция 1.8.2.

## Команды на сервере (после Stage 2)

Через SSH, на сервере:

```bash
sudo /opt/primetime/deploy/invites.sh create 3 days=14 note=друзья
sudo /opt/primetime/deploy/invites.sh list
sudo /opt/primetime/deploy/invites.sh list all
sudo /opt/primetime/deploy/invites.sh stats
sudo /opt/primetime/deploy/invites.sh revoke <id или код>
```

На сервере параметры пишутся как `days=14`, `uses=1`, `note=текст` (без `--`). Скрипт запускает консольную команду PocketBase от имени пользователя `pocketbase` с настройками сервера.

## Как раздавать

1. Один код — один человек. Отправьте его лично, в своём мессенджере.
2. В `note` пишите только то, что нужно вам, чтобы узнать человека: имя или ник. Телефоны и адреса туда не пишите.
3. **Нельзя публиковать действующие коды:**
   - в GitHub, README и документации;
   - в скриншотах, чатах с посторонними и публичных постах.
4. Если код утёк, отзовите его: `revoke`. Аккаунты, уже созданные по нему, останутся.
5. Скажите тестировщику, что это тестовая версия: прогресс может быть сброшен, а официальных правил и политики конфиденциальности пока нет (см. чек-лист).

## Что видит тестировщик

PRIME ID → блок PRIME NETWORK со значком **CLOSED BETA**:

> Регистрация пока доступна только приглашённым участникам тестирования. Без кода можно продолжать играть как гость.

Кнопка «Есть приглашение — создать аккаунт» открывает форму с полем **«Код приглашения»**. Ошибки:

| Ситуация | Текст в игре |
|---|---|
| код не введён | «Введите код приглашения.» |
| опечатка, код обрезан, несуществующий или отозванный код | «Код приглашения неверный. Проверьте, что он скопирован целиком.» |
| код уже использован | «Этот код приглашения уже использован.» |
| срок истёк | «Срок действия кода приглашения истёк. Попросите новый.» |
| регистрация закрыта (`disabled`) | «Регистрация временно недоступна. Вход в существующий аккаунт работает.» |

Код вводится **только при создании аккаунта**. Вход, подтверждение email, восстановление пароля и синхронизация кода не требуют.

Пока на сервере нет почты, после регистрации тестировщик видит «Аккаунт ожидает проверки». Организатор подтверждает аккаунт вручную в панели PocketBase, когда убедился вне игры, что email принадлежит этому человеку. Порядок действий — [PRIME_BETA_PUBLISH.md](PRIME_BETA_PUBLISH.md), раздел 4.

## Режим регистрации

| Где | Как поменять |
|---|---|
| Mac | `npm run backend` — закрытая бета (по умолчанию). Варианты: `npm run backend -- --registration disabled` или `npm run backend -- --registration public` (только для локальных тестов) |
| сервер | строка `PRIME_REGISTRATION=` в `/etc/primetime/pocketbase.env`, затем `sudo systemctl restart pocketbase` |

Подробно о режимах — [PRIME_CLOUD_PREDEPLOY.md](PRIME_CLOUD_PREDEPLOY.md), раздел 2. **`public` на сервере не включать до публичного запуска** и юридической подготовки.
