# PRIME CLOUD — чек-лист перед закрытой бетой

Здесь собрано то, что **решает разработчик**: покупки, выбор сервисов и юридические вопросы. Автоматически ничего из этого не выбрано и не куплено. Юридический раздел — список вопросов, а не готовые решения или документы.

---

## 1. Покупки и выбор сервисов (ваше решение)

| Что | Зачем | Статус |
|---|---|---|
| VPS с Ubuntu 24.04 LTS (например, Timeweb Cloud) | сервер PRIME NETWORK | не куплен — ждёт разрешения на Stage 2 |
| Домен или поддомен для API (`api.…`) | HTTPS-сертификат, переезд без новой сборки игры | не выбран |
| Почтовый провайдер (SMTP) | письма подтверждения email и смены пароля | не выбран; без него друзья не смогут подтвердить email |
| Внешнее место для копий | копии вне VPS | бесплатный вариант — забирать на Mac (см. [BACKUP](PRIME_CLOUD_BACKUP.md)); платные не подключались |
| Менеджер паролей | `pocketbase.env`, пароль суперпользователя, ключ `age` | ваш выбор |

Перед покупкой посмотрите:

- **где находится дата-центр** — это важно для юридических вопросов ниже;
- есть ли резервное копирование у самого провайдера и сколько оно стоит;
- можно ли добавить SSH-ключ при создании сервера.

## 3. Юридические вопросы (решения принимает разработчик)

Это **не юридическая консультация** и не готовые документы. Это вопросы, на которые нужно ответить самостоятельно или с юристом до того, как собирать данные реальных людей на публичном сервере. В игре сейчас стоит честная пометка о тестовой версии. Формальных галочек согласия и «политики» нет специально.

**Какие данные собирает PRIME NETWORK:**

- email;
- никнейм;
- хеш пароля (сам пароль не хранится);
- игровое сохранение;
- время входа и синхронизации;
- IP-адреса в журналах Caddy и PocketBase;
- пометки в приглашениях (`note`).

**Вопросы:**

1. **Персональные данные.** Являетесь ли вы оператором персональных данных? Какие обязанности из этого следуют там, где вы живёте и где живут тестировщики? Например, для России — 152-ФЗ: уведомление Роскомнадзора, требования к месту хранения данных граждан РФ. Для тестировщиков из ЕС — GDPR.
2. **Где сервер.** В какой стране будет дата-центр VPS? Подходит ли это под ответ на вопрос 1?
3. **Политика конфиденциальности.** Нужна ли она уже для закрытой беты с друзьями или только для публичного запуска? Кто её пишет и проверяет?
4. **Правила пользования (соглашение).** Тестовая версия, прогресс может быть сброшен, сервис может быть остановлен. Как и где это показать?
5. **Согласие.** Нужно ли отдельное согласие на обработку данных и на письма? В какой форме? Галочки «для вида» не добавлялись — только по вашему решению.
6. **Возраст.** Могут ли тестировщики быть несовершеннолетними? Что тогда требуется?
7. **Удаление данных.** Как тестировщик просит удалить аккаунт, кто и в какой срок это делает? Технически это уже возможно: суперпользователь удаляет аккаунт в панели, а профиль, облачное сохранение и история удаляются вместе с ним (проверено в `npm run beta:test`). Остаются копии в резервных архивах — сколько их хранить (сейчас 14 дней)?
8. **Журналы.** Сколько хранить журналы с IP-адресами? Сейчас Caddy хранит до 5 файлов по 10 МБ.
9. **Почтовый провайдер и VPS** обрабатывают данные по вашему поручению. Нужен ли с ними договор или приложение об обработке данных?
10. **Контент игры для публичного запуска.** Права на музыку (MP3-саундтрек), звуки, шрифты (Rubik и Unbounded — лицензия OFL) и библиотеки (three.js, PocketBase — MIT). Название «PRIME TIME: SHOWDOWN» и студия «NEON NIGHT PRODUCTIONS» — нет ли конфликтов с товарными знаками?
11. **Монетизация.** Её нет. Если появится — отдельные вопросы: налоги, оферта, возвраты.

## 4. Список действий разработчика

**Сейчас (Stage 1, на Mac):**

1. Прочитать [PRIME_CLOUD_PREDEPLOY.md](PRIME_CLOUD_PREDEPLOY.md). Главное — раздел «Что НЕ проверено».
2. Скопировать `backups-private/pb_data-2026-10-18_221817-before-1.8.2.zip` на внешний диск или флешку.
3. Запустить локальный backend: `npm run backend`. Миграция 1.8.2 применится к вашей базе, это проверено на копии. Затем создать себе код `npm run invites -- create 1` и попробовать регистрацию по приглашению в `npm run dev:accounts` (подробно — [ACCOUNTS_LOCAL.md](ACCOUNTS_LOCAL.md)).
4. При копировании проекта в папку GitHub **не копировать**:
   - `backups-private/`;
   - `backend/bin/`, `backend/pb_data/`, `backend/backups/`;
   - `server-bundle/`;
   - `.env.*.local` и любые настоящие `deploy/**/*.env`.

   `.gitignore` их и так не пропустит в git, но лучше не класть их туда вовсе. Публиковать 1.8.2 Stage 1 не обязательно: опубликованная игра остаётся гостевой.
5. Ответить себе на вопросы раздела 1 (покупки) и раздела 3 (юридические).

**После Stage 1 — только по отдельному разрешению на Stage 2.** Это действия, для которых нужны именно вы:

1. Выбрать бюджетный тариф Timeweb Cloud с Ubuntu 24.04 LTS.
2. Выбрать регион сервера. Сначала ответьте на юридические вопросы 1–2 (где можно хранить персональные данные тестировщиков).
3. Создать VPS, добавить свой SSH-ключ.
4. Получить IP сервера и доступ администратора (root по SSH-ключу). Пароль root нигде не пересылать.
5. Определить домен или поддомен API, создать DNS-запись `A` (см. [DEPLOY](PRIME_CLOUD_DEPLOY.md), шаг 1).
6. Выбрать способ отправки настоящих писем (SMTP-провайдер). До этого письма не уходят, и друзья не смогут подтвердить email.
7. Решить, какие условия и тексты нужны для закрытого теста (раздел 3), и подготовить их.
8. Выполнить развёртывание по [PRIME_CLOUD_DEPLOY.md](PRIME_CLOUD_DEPLOY.md), отмечая пункты раздела 2 этого файла.
9. Проверить аккаунт с Mac: регистрация по своему коду, письмо, вход, синхронизация.
10. Проверить аккаунт с iPhone: то же самое плюс конфликт двух устройств.
11. Создать несколько приглашений для друзей ([INVITES](PRIME_CLOUD_INVITES.md)).
12. Провести закрытое тестирование: раз в неделю забирать копию базы на Mac ([BACKUP](PRIME_CLOUD_BACKUP.md), раздел 3).

**Пока нельзя:**

- включать `PRIME_REGISTRATION=public`;
- передавать кому-либо доступ к панели администратора или `pocketbase.env`;
- публиковать действующие коды приглашений;
- объявлять публичный запуск.
