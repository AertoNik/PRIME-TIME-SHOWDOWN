# Сезонные события PRIME TIME: SHOWDOWN

Эта инструкция объясняет, как устроены сезоны и как управлять ими без глубокого программирования. Почти всё меняется в трёх конфигурационных файлах в папке `src/config/`.

| Файл | Что в нём |
|---|---|
| `src/config/events.config.ts` | Режим (авто/ручной), календарь событий, задания, жетоны, обмен наград |
| `src/config/themes.config.ts` | Темы оформления: цвета интерфейса, арена, вывески, свет, декорации |
| `src/config/cosmetics.config.ts` | Косметические награды: названия, описания, слот, где видна |

Код, который это выполняет (обычно трогать не нужно):

- `src/meta/EventManager.ts` — календарь, задания, жетоны, обмен, коллекция, сохранения;
- `src/game/ThemeManager.ts` — переключение оформления (интерфейс, арена, эффекты, звук);
- `src/render/SeasonalDecor.ts` — 3D-декорации арены (тыквы, летучие мыши, снег и т. д.);
- `src/ui/screens/EventsScreen.ts` — экран «События».

---

## 1. Ручное и автоматическое переключение

Откройте `src/config/events.config.ts`. В самом начале есть блок:

```ts
export const eventSettings: EventSettings = {
  mode: 'auto',
  forcedEventId: 'halloween-2026',
};
```

- `mode: 'auto'` — **обычный режим для публикации**. Игра сама включает событие по датам из календаря и сама выключает его после окончания.
- `mode: 'manual'` — игра всегда показывает событие из `forcedEventId`, даты не важны.

Значения `forcedEventId`:

| Значение | Что будет |
|---|---|
| `'halloween-2026'` | Хэллоуин: тема, задания, жетоны, награды |
| `'winter-preview'` | Зимнее оформление (только внешний вид, без заданий) |
| `'none'` | Стандартное оформление PRIME TIME |

### Как вручную включить Хэллоуин

```ts
mode: 'manual',
forcedEventId: 'halloween-2026',
```

### Как вернуть стандартную тему

```ts
mode: 'manual',
forcedEventId: 'none',
```

### Как посмотреть зимнее оформление

```ts
mode: 'manual',
forcedEventId: 'winter-preview',
```

### Как включить автоматический календарь

```ts
mode: 'auto',
```

(`forcedEventId` в режиме `auto` ни на что не влияет.)

> ⚠️ Перед публикацией верните `mode: 'auto'`. В ручном режиме событие увидят все игроки, независимо от дат.
> Если указать несуществующий `forcedEventId`, игра спокойно включит стандартную тему.

## 2. Быстрая проверка без правки файлов (только при разработке)

При запуске через `npm run dev` можно дописать параметры к адресу:

| Адрес | Что делает |
|---|---|
| `http://localhost:5173/?event=halloween-2026` | включить Хэллоуин |
| `http://localhost:5173/?event=winter-preview` | зимнее оформление |
| `http://localhost:5173/?event=none` | стандартная тема |
| `http://localhost:5173/?now=2026-10-25` | «притвориться», что сегодня 25 октября 2026 (проверка автоматического календаря) |
| `http://localhost:5173/?now=2026-11-05` | проверить, что после окончания события вернулась стандартная тема |

Эти параметры **работают только в `npm run dev`**. В опубликованной игре на GitHub Pages они игнорируются, поэтому игроки не могут включить чужой сезон и получить его награды.

## 3. Календарь

Каждое событие в массиве `EVENTS` имеет даты:

```ts
start: '2026-10-20T00:00:00Z',  // начало (включительно), время UTC
end:   '2026-11-04T00:00:00Z',  // конец (НЕ включительно): 4 ноября 00:00 событие уже закончилось
announceDays: 14,               // за сколько дней до начала показывать анонс «Скоро»
```

- До начала (в пределах `announceDays`) в меню и в «Событиях» виден анонс с обратным отсчётом.
- Во время события тема, задания и обмен включены.
- После окончания возвращается стандартная тема, задания и обмен закрываются, **полученные предметы остаются**.

> Ограничение: игра работает на статическом GitHub Pages без сервера и берёт время с устройства. Если игрок переведёт часы, событие у него может включиться раньше. Для бесплатных косметических наград это допустимо. Если в будущем появятся платные вещи, время нужно будет брать с сервера: для этого в `EventManager` есть отдельный «источник времени» (`clock`), который заменяется одной строкой.

## 4. Как добавить новое событие

1. Откройте `src/config/events.config.ts` и скопируйте объект `halloween-2026` в массиве `EVENTS`.
2. Поменяйте:
   - `id` — уникальное имя, например `'winter-2026'` (по нему сохраняется прогресс игроков, после публикации не меняйте);
   - `title`, `subtitle`, `tagline` — тексты;
   - `themeId` — какая тема оформления (`'halloween'`, `'winter'` или новая);
   - `start`, `end` — даты;
   - `currency` — сезонная валюта (название и иконка: `'pumpkin'` или `'snowflake'`);
   - `earnings` — сколько жетонов дают бои (см. раздел 6);
   - `quests` — задания (раздел 5);
   - `shop` и `grandPrize` — награды (раздел 7).
3. Проверьте в ручном режиме (`mode: 'manual'`, `forcedEventId: 'ваш-id'`) или через `?event=ваш-id`.
4. Верните `mode: 'auto'` и опубликуйте. Событие само включится в нужные даты.

Событие без заданий и валюты (как `winter-preview`) работает как «просто оформление».

## 5. Как создавать задания

Задание — это объект в списке `quests`:

```ts
{ id: 'first_night', title: 'FIRST NIGHT ON AIR', desc: 'Победите в 3 матчах',
  metric: { kind: 'wins' }, target: 3, reward: 30, icon: 'moon' },
```

- `id` — уникальное имя внутри события;
- `title` и `desc` — то, что видит игрок;
- `metric` — что считать (таблица ниже);
- `target` — сколько нужно;
- `reward` — сколько сезонных жетонов игрок получит, нажав «Забрать»;
- `icon` — `moon`, `combo`, `star`, `ghost`, `clock`, `crown` или `tv`.

Доступные `metric` (считаются только по-настоящему завершённым боям, сданный бой не засчитывается). Режим SURVIVAL засчитывается как **один** бой за всю попытку (комбо и идеальные реакции всех волн суммируются), испытание PRIME CHALLENGE — как обычный бой:

| metric | Что считает |
|---|---|
| `{ kind: 'wins' }` | победы |
| `{ kind: 'matches' }` | проведённые матчи |
| `{ kind: 'combos' }` | количество комбо |
| `{ kind: 'ultraCombos' }` | ультра-комбо (ELECTRO BLAST, SUPERSTAR MOVE) |
| `{ kind: 'perfects' }` | идеальные уклонения и блоки |
| `{ kind: 'koWins' }` | победы нокаутом |
| `{ kind: 'ratingSum' }` | сумма рейтинга шоу за все матчи |
| `{ kind: 'ratingAtLeast', min: 80 }` | матчи с рейтингом не ниже `min` |
| `{ kind: 'winsOnDifficulty', min: 'pro' }` | победы на сложности `min` или выше (`rookie`, `pro`, `champion`) |

Награда за задание выдаётся один раз: после «Забрать» задание отмечается как полученное и повторно не платит.

## 6. Сезонная валюта (жетоны)

```ts
currency: { id: 'pumpkin', name: 'PUMPKIN TOKENS', short: ['жетон', 'жетона', 'жетонов'], icon: 'pumpkin' },
earnings: { win: 4, rating: [[60, 2], [85, 2]], perCombo: 1, comboCap: 3, dailyCap: 60 },
```

За каждый завершённый бой во время события:

- победа: `win` жетонов;
- рейтинг: за каждый достигнутый порог (`[60, 2]` — рейтинг 60+ даёт 2 жетона);
- комбо: `perCombo` за каждое, но не больше `comboCap`;
- в день из боёв можно получить не больше `dailyCap` жетонов (защита от бесконечного фарма). Награды за задания в лимит не входят.

У каждого события своя валюта и свой счёт. Жетоны прошедшего события сохраняются в истории, но тратить их можно только пока событие идёт.

## 7. Как добавить косметическую награду

1. В `src/config/cosmetics.config.ts` добавьте предмет в `COSMETICS` (и его id в тип `CosmeticId`): название, описание, `slot` (куда он «надевается»), `art` (картинка) и `rarity`.
2. Добавьте предмет в событие:
   - в обмен: `shop: [{ cosmetic: 'ваш_id', cost: 150 }]`;
   - или главным призом: `grandPrize: { cosmetic: 'ваш_id', questsNeeded: 6 }`.
3. Задайте внешний вид для слота:

| Слот | Где показывается | Где настраивается вид |
|---|---|---|
| `cardStyle` | рамки карт в бою и в колоде | `src/styles/main.css`, блок `data-card-style` |
| `broadcastFrame` | рамка трансляции в бою и табличка бойца | `main.css`, блок `data-frame` |
| `dashFx` | цвет следа рывка DASH | `src/render/BattleView.ts` (`PHANTOM`) |
| `victoryFx` | эффект победы | `BattleView.ts` (`pumpkins`) |
| `title` | титул в меню и стиль победного экрана | `main.css` (`champ-ribbon`) и `ResultsScreen.ts` |

Новые предметы сразу надеваются. Игрок может снять или надеть их в «События → Награды» (или «Коллекция», когда события нет).

## 8. Как добавить новую тему оформления

В `src/config/themes.config.ts` скопируйте тему `winter` и поменяйте:

- `css` — цвета интерфейса (кнопки, панели, акценты). Это CSS-переменные: менять можно только значения;
- `arena` — свет, цвета прожекторов, неоновые надписи, LED-ленту спонсоров, тексты на большом экране, декорации (`decor`: `'pumpkins'`, `'frost'` или `'none'`) и парящие частицы (`ambient`: `'spirits'`, `'snow'` или `'none'`);
- `vfx` — цвета вспышек комбо и конфетти;
- `ui.decor` — украшения меню (`'cobweb'`, `'frost'` или `'none'`);
- `sting` — короткий звук при открытии «Событий».

Затем добавьте id темы в тип `ThemeId` и укажите её в событии (`themeId`). Новые виды 3D-декораций добавляются в `src/render/SeasonalDecor.ts`.

## 9. Как работает сохранение

Всё хранится в `localStorage` браузера в том же сохранении, что и карьера (ключ не менялся; формат версии 3, с Alpha 1.3 — версии 4):

- `events` — по каждому событию: жетоны, сколько заработано и потрачено, прогресс и получение заданий, купленные предметы, главный приз;
- `cosmetics` — коллекция (`owned`), что надето (`equipped`) и история получения (`history`).

Старые сохранения Alpha 1.0, 1.1 и 1.1.1 загружаются без потерь: недостающие поля создаются пустыми. Повреждённые данные очищаются, а надеть можно только предмет, который реально есть в коллекции.

> Важно: `localStorage` — это хранилище на устройстве игрока, а не защищённая база. Игрок может его изменить. Для бесплатных наград это нормально; для настоящих покупок понадобится сервер.
