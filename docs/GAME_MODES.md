# Режимы эфира PRIME TIME: SHOWDOWN (Alpha 1.3)

Как устроены SURVIVAL и PRIME CHALLENGE и как их настраивать. Почти всё меняется в одном файле — `src/config/modes.config.ts`.

| Файл | Что в нём |
|---|---|
| `src/config/modes.config.ts` | Волны Survival, лечение, бонусы, награды; список испытаний Prime Challenge |
| `src/meta/GameModes.ts` | Правила: ход марафона, бонусы, проверка испытаний, рекорды, разовые награды |
| `src/combat/Match.ts` | `MatchMods` — модификаторы одного боя (время, энергия, здоровье, урон) |
| `src/ui/screens/ModesScreen.ts` | Экран «Режимы эфира» |
| `src/ui/screens/SurvivalScreen.ts` | Перерыв между волнами (бонус) и итог марафона |

Все режимы используют один и тот же движок боя. Отличия передаются через `MatchMods` и живут только внутри одного матча, поэтому после выхода из режима ничего не переносится в обычную дуэль.

## 1. SURVIVAL

Блок `SURVIVAL` в `modes.config.ts`:

```ts
waves: [
  { difficulty: 'rookie', hpMult: 0.85, dmgMult: 0.9, reward: { money: 150, fans: 130, rep: 8 } },
  ...
],
healBetween: 0.2,      // лечение после победы (доля максимума)
ratingMoney: 1.8,      // $ за каждое очко рейтинга пройденной волны
completion: { ... },   // бонус за все 5 волн
firstClear: { ... },   // разовый бонус за первое полное прохождение
participation: { ... },// утешительный гонорар, если не пройдена ни одна волна
```

- `difficulty` — уровень ИИ соперника (`rookie`, `pro`, `champion`).
- `hpMult` / `dmgMult` — дополнительные множители здоровья и урона соперника поверх сложности.
- Количество волн = длина массива `waves`.
- Соперники выбираются из всех ИИ-противников (`RIVAL_ORDER` в `fighters.ts`) в случайном порядке, один и тот же соперник не выходит два раза подряд.

### Бонусы между волнами

Блок `PERKS`: `value` — сила эффекта, `maxStacks` — сколько раз можно взять за попытку.

| Бонус | Эффект |
|---|---|
| SECOND WIND | сразу лечит `value` (0.3 = 30%) |
| ENERGY BOOST | энергия копится быстрее на `value` за каждый взятый раз |
| POWER SURGE | урон бойца больше на `value` за каждый взятый раз |

### Что происходит с попыткой

- После старта и после каждой волны попытка записывается в сохранение (`modes.survival.active`).
- Награда выдаётся **один раз** при завершении: поражение, ничья, сдача, «Завершить марафон» или пятая победа.
- Если игру закрыть посреди марафона, при следующем запуске попытка засчитывается с уже пройденными волнами и показывается сообщение «Марафон прерван». Повторить волну перезагрузкой нельзя.
- Сезонное событие получает весь марафон как **один** бой: победа — только за полное прохождение, рейтинг — средний по волнам, комбо и идеальные реакции — сумма всех волн. Сдача и прерванная попытка событию не засчитываются.

## 2. PRIME CHALLENGE

Каждое испытание — объект в массиве `CHALLENGES`:

```ts
{
  id: 'spotlight',                 // не менять после публикации: по нему хранится прогресс
  title: 'PRIME SPOTLIGHT',
  quote: 'Одной победы мало...',   // слоган на карточке
  rules: ['...', '...'],           // правила, которые игрок видит до старта
  rival: 'dex',                    // соперник
  mods: { duration: 55, energyMult: 1.5, rivalEnergyMult: 1.25 },  // модификаторы боя
  goal: { win: true, minRating: 80, timeUpMargin: 0.1 },           // условие прохождения
  goalShort: 'ПОБЕДА + РЕЙТИНГ 80', // коротко для HUD и списка
  hudTag: 'SPOTLIGHT',             // короткое имя в полоске HUD
  record: 'rating',                // рекорд: 'combos' | 'fastest' | 'rating'
  moneyMult: 1,                    // множитель гонорара за бой
  firstClear: { money: 450, rep: 35 },  // разовая награда за первое прохождение
  icon: 'spotlight',               // иконка: 'energy_rush' | 'high_stakes' | 'spotlight'
}
```

Условия `goal` (можно сочетать):

| Поле | Значение |
|---|---|
| `win: true` | нужна победа (всегда) |
| `minRating` | итоговый рейтинг шоу не ниже значения |
| `timeUpMargin` | если бой закончился по времени, нужен перевес здоровья не меньше этой доли |

### Как добавить новое испытание

1. Скопируйте объект в `CHALLENGES` и задайте новый `id`.
2. Поменяйте тексты, соперника, `mods`, `goal` и награды.
3. Проверьте: `npm run modes` (там же отчёт, как часто испытание проходят боты) и `npm run build`.

Экран режимов, подготовка, HUD и итоговый экран подхватят испытание автоматически.

## 3. Награды и экономика

- Новых валют нет: деньги, фанаты и репутация продюсера.
- Бой испытания оплачивается как обычный бой (с `moneyMult`) и засчитывается в карьеру, но **не меняет** следующего соперника обычной дуэли.
- Награда за первое прохождение испытания и за первый полный марафон сохраняется вместе с отметкой о выплате — повторно её получить нельзя, в том числе после перезагрузки.

## 4. Сохранения

Версия сохранения 4, ключ прежний. Новые данные — блок `modes`:

- `modes.survival` — попытки, полные прохождения, лучшая волна и очки, лучший результат каждого бойца, дата рекорда, отметка разового бонуса, текущая попытка;
- `modes.challenges[id]` — попытки, прохождения, дата первого прохождения, рекорд.

Старые сохранения получают пустые рекорды, остальное не меняется.

## 5. Проверки

```bash
npm run modes
```

Правила режимов, разовые награды, перезагрузка посреди марафона, сезонные события, сохранения и отчёт по балансу. Без отчёта по балансу (быстрее): `npm run modes -- 0`.

```bash
npm run build
```
