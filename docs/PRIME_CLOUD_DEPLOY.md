# PRIME CLOUD — как поставить сервер закрытой беты на VPS

> **Это инструкция для Stage 2. Сейчас её не выполнять.** Сервер не покупать и игру не публиковать до отдельного разрешения. Набор файлов подготовлен и проверен на Mac, но на настоящем Linux-сервере ещё ни разу не запускался. Первый запуск делайте по шагам и читайте вывод каждой команды.

Цель: Ubuntu 24.04 LTS на VPS (например, Timeweb Cloud), домен `api.ВАШ-ДОМЕН`, PocketBase за Caddy с HTTPS, закрытая регистрация по приглашениям.

В примерах:

- `203.0.113.10` — IP сервера (замените на свой);
- `api.example.com` — домен API (замените на свой).

Команды с `$` в начале строки вводятся без `$`.

---

## 0. Что нужно до начала

- [ ] Разрешение на Stage 2.
- [ ] VPS с **Ubuntu 24.04 LTS**, 1 vCPU и 1–2 ГБ памяти хватит для закрытой беты. Выбор тарифа — ваше решение, см. [PRIME_CLOUD_LAUNCH_CHECKLIST.md](PRIME_CLOUD_LAUNCH_CHECKLIST.md).
- [ ] Домен или поддомен, у которого вы можете менять DNS-записи.
- [ ] SSH-ключ на Mac. Если его нет:

  ```bash
  ssh-keygen -t ed25519
  ```

  Публичная часть лежит в `~/.ssh/id_ed25519.pub`. Её добавляют в панели провайдера при создании сервера. Закрытую часть никому не отправляйте.
- [ ] Свежая сборка проверок на Mac: `npm run build && npm run accounts && npm run beta:test`.

## 1. DNS

В панели, где куплен домен, создайте запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `api` | IP сервера |

Подождите, пока запись заработает (обычно минуты, иногда до суток). Проверка на Mac:

```bash
dig +short api.example.com
```

Должен вывестись IP сервера. Без этого Caddy не получит HTTPS-сертификат.

Если у провайдера VPS в панели есть свой firewall, откройте в нём порты **22, 80 и 443**.

## 2. Собрать архив для сервера (на Mac)

```bash
cd ~/Desktop/"PRIME TIME Duel"
npm run server:bundle
```

Появится `server-bundle/prime-server-<версия>.tar.gz` и файл с его SHA-256. Внутри только код сервера, шаблоны и эти инструкции. В архив не попадают:

- база;
- резервные копии;
- программы;
- настоящие настройки;
- служебные файлы macOS. Файлы вида `._prime.pb.js` сломали бы запуск PocketBase, поэтому не упаковывайте папку вручную через Finder.

## 3. Загрузить файлы на сервер

```bash
scp server-bundle/prime-server-*.tar.gz* root@203.0.113.10:/root/
```

Войдите на сервер:

```bash
ssh root@203.0.113.10
```

Дальше команды выполняются **на сервере**:

```bash
$ cd /root
$ sha256sum -c prime-server-*.tar.gz.sha256
$ mkdir -p prime && tar -xzf prime-server-*.tar.gz -C prime && cd prime
```

`sha256sum` должен ответить `OK`.

## 4. Установка

```bash
$ sudo bash deploy/linux/install.sh api.example.com
```

Скрипт выводит каждый шаг (`==> …`):

1. Ставит пакеты Ubuntu: `unzip sqlite3 curl caddy ufw age`.
2. Создаёт системного пользователя `pocketbase` без входа в систему.
3. Скачивает **PocketBase 0.40.5** с GitHub и сверяет SHA-256 с `backend/versions.json`. При несовпадении ничего не ставится.
4. Копирует серверный код в `/opt/primetime`.
5. Создаёт `/etc/primetime/pocketbase.env` из шаблона:
   - генерирует новый ключ шифрования `PB_ENCRYPTION_KEY`;
   - записывает адрес `https://api.example.com`.

   Если файл уже есть, не трогает его.
6. Ставит службы `pocketbase` и `prime-backup.timer` (ежедневная копия в ~03:30 UTC).
7. Пишет `/etc/caddy/Caddyfile`; старый сохраняется как `Caddyfile.original`. Проверяет его командой `caddy validate`.
8. Firewall: разрешает только OpenSSH, 80 и 443, затем включает его.
9. Запускает всё и выводит `healthcheck`.

Повторный запуск безопасен: база и файл настроек не перезаписываются.

**Сразу после установки сохраните копию `/etc/primetime/pocketbase.env`** в личных заметках или менеджере паролей:

```bash
$ sudo cat /etc/primetime/pocketbase.env
```

Без `PB_ENCRYPTION_KEY` из этого файла PocketBase не запустится с этой базой — ни здесь, ни на другом сервере. Это проверено: `npm run beta:test`, раздел «Перенос базы».

Если `apt` не находит пакет `caddy`, поставьте Caddy по официальной инструкции на caddyserver.com (раздел Install → Debian, Ubuntu, Raspbian) и запустите `install.sh` ещё раз.

## 5. Проверка

```bash
$ sudo /opt/primetime/deploy/healthcheck.sh api.example.com
```

Всё должно быть `OK`:

- служба работает;
- PocketBase отвечает локально;
- `https://api.example.com/api/health` отвечает (сертификат действителен);
- режим регистрации — `invite_only`;
- панель `/_/` из интернета — 404.

Пункт про резервные копии станет `OK` после первой копии:

```bash
$ sudo systemctl start prime-backup
```

С Mac:

```bash
curl https://api.example.com/api/health
curl https://api.example.com/api/prime/config
```

## 6. Панель администратора (только через SSH-туннель)

Из интернета панель закрыта. Caddy отвечает 404 на `/_/` и на служебные адреса суперпользователя. Чтобы открыть её, на **Mac** в отдельной вкладке Терминала выполните:

```bash
ssh -N -L 18090:127.0.0.1:8090 root@203.0.113.10
```

Пока команда работает, панель сервера доступна на Mac по адресу `http://127.0.0.1:18090/_/`. Порт 18090 выбран, чтобы не перепутать сервер с локальным backend на 8090. Закрыть туннель — Ctrl+C. Проверки проекта (`npm run backend:test`, `beta:test`) этот порт не используют и не запускаются, если их собственные порты чем-то заняты, — так их запросы никогда не уйдут через туннель на настоящий сервер.

**Первый суперпользователь.** При первом запуске PocketBase пишет ссылку установки в журнал:

```bash
$ sudo journalctl -u pocketbase --no-pager | grep pbinstall
```

Ссылка выглядит как `http://127.0.0.1:8090/_/#/pbinstall/…`. Откройте её на Mac при работающем туннеле, **заменив `8090` на `18090`**. Задайте отдельный email и длинный пароль администратора. Если ссылка устарела, выполните `sudo systemctl restart pocketbase` и возьмите новую.

Доступ к панели не передавайте никому, в том числе тестировщикам.

## 7. Почта

Пока в `/etc/primetime/pocketbase.env` в `PRIME_MAIL_MODE` не стоит `smtp`, сервер **не отправляет писем**. С серверным кодом из Alpha 1.8.2 closed beta он и не пытается: игре сообщается `mail:false`, игрок видит «Аккаунт ожидает проверки», а организатор подтверждает аккаунт вручную. Подробно — [PRIME_BETA_PUBLISH.md](PRIME_BETA_PUBLISH.md), раздел 4.

Варианты:

- **Закрытый технический тест (сейчас).** Панель (шаг 6) → Collections → `users` → аккаунт → включить **verified** → «Yes, verify» → **Save changes**. Для чужих аккаунтов — только после того, как вы убедились вне игры, что email принадлежит этому человеку.
- **Для друзей.** Сначала выберите почтового провайдера (это ваше решение, см. чек-лист). Затем заполните `PRIME_SENDER_*`, `PRIME_SMTP_*` и `PRIME_MAIL_MODE=smtp`:

  ```bash
  $ sudo nano /etc/primetime/pocketbase.env
  $ sudo systemctl restart pocketbase
  ```

  Значения с пробелами берите в двойные кавычки, как в шаблоне. Первое письмо отправьте **на свой** адрес: зарегистрируйте свой аккаунт по приглашению.

## 9. Игра для закрытой беты (отдельный шаг публикации)

Только когда сервер проверен и есть разрешение на публикацию. В папке проекта на Mac создайте файл `.env.production`:

```
VITE_PRIME_ACCOUNTS=beta
VITE_PRIME_API_URL=https://api.example.com
```

Затем выполните `npm run build && npm run accounts`. Сборка должна содержать адрес сервера.

Дальше — обычная публикация: скопировать файлы в папку GitHub, Commit, Sync. GitHub Actions соберёт игру с этим файлом. Файл `.env.production` содержит только публичный адрес и **должен** попасть в репозиторий. Если в нём окажется что-то ещё, кроме этих двух строк, — остановитесь.

Убедитесь, что `PRIME_ORIGINS` в настройках сервера — `https://aertonik.github.io`, без пути. Иначе браузер не пустит игру к серверу (CORS).

## 10. Обновление сервера

На Mac:

```bash
npm run server:bundle
```

Загрузите новый архив (шаг 3) в **новую** папку, например `/root/prime-new`, и выполните на сервере:

```bash
$ cd /root/prime-new && sudo bash deploy/linux/update.sh
```

`update.sh` по шагам:

1. Делает свежую копию базы. Если копия не создалась, ничего не меняет.
2. Заменяет код, сохраняя прежний как `*.previous`.
3. Перезапускает PocketBase. Новые миграции применяются при запуске.
4. Если PocketBase не ответил за 30 секунд, возвращает прежний код и печатает команду восстановления копии из шага 1.

Службы systemd и `Caddyfile` при обновлении не меняются. Если они изменились, используйте `install.sh`.

## 11. Журналы

| Что | Команда |
|---|---|
| PocketBase | `sudo journalctl -u pocketbase -n 100 --no-pager` |
| Caddy (сертификаты, ошибки) | `sudo journalctl -u caddy -n 100 --no-pager` |
| Запросы к API | `sudo tail -n 50 /var/log/caddy/primetime-access.log` |
| Резервные копии | `sudo journalctl -u prime-backup -n 20 --no-pager` |
| Следующая копия | `systemctl list-timers prime-backup.timer` |

В журнале запросов есть IP-адреса игроков — это персональные данные. Не публикуйте его.

## 12. Если что-то пошло не так

| Признак | Что проверить |
|---|---|
| `https://…` не отвечает | `dig +short` показывает IP сервера? порты 80/443 открыты у провайдера? `journalctl -u caddy` |
| PocketBase не запускается, в журнале `message authentication failed` | в `pocketbase.env` не тот `PB_ENCRYPTION_KEY` — верните прежний из заметок |
| Игра пишет «сервер недоступен», а `curl` работает | `PRIME_ORIGINS` (CORS) и адрес в `.env.production` |
| Письма не приходят | `PRIME_MAIL_MODE=smtp`? данные SMTP? `journalctl -u pocketbase` |
| Регистрация «закрыта», хотя нужен invite_only | ровно `PRIME_REGISTRATION=invite_only` (маленькие буквы, подчёркивание), затем `sudo systemctl restart pocketbase` |
| Нужно вернуть базу | [PRIME_CLOUD_BACKUP.md](PRIME_CLOUD_BACKUP.md) → «Восстановление на сервере» |

Отключить регистрацию полностью, не трогая существующие аккаунты: поставьте в `pocketbase.env` `PRIME_REGISTRATION=disabled` и выполните `sudo systemctl restart pocketbase`.

## 13. Безопасно остановить сервер

```bash
$ sudo systemctl stop pocketbase
```

Как понять, что получилось:

- `systemctl is-active pocketbase` отвечает `inactive`;
- игра показывает «Сервер PRIME NETWORK сейчас недоступен», гостевая игра работает.

PocketBase завершается сам и аккуратно, база не повреждается. Запуск — `sudo systemctl start pocketbase`.

Перед выключением или перезагрузкой VPS из панели провайдера сначала выполните `systemctl stop`. После загрузки служба запустится сама.

Не останавливайте сервер через `kill -9` и не копируйте файл базы вручную при работающем PocketBase. Для копий есть `prime-backup`.

## 14. Что нельзя удалять на сервере

| Путь | Что это |
|---|---|
| `/var/lib/primetime/pb_data/` | **сама база**: аккаунты, сохранения, приглашения |
| `/etc/primetime/pocketbase.env` | настройки и **ключ шифрования** — без него база не запустится |
| `/var/backups/primetime/` | резервные копии |
| `/var/lib/primetime/pb_data.before-restore-…` | данные до последнего восстановления — удалять, только когда новая база точно в порядке |
| `/opt/primetime/*.previous` | код до последнего обновления (для отката) |

Пользователей, файлы и папки в панели PocketBase руками не удаляйте. Исключение — удаление аккаунта по просьбе тестировщика (см. чек-лист, вопрос 7).
