# Alpha 1.8.4 «PRIME NETWORK» — публичная регистрация и безопасность аккаунтов

> Ничего на сервере, в DNS, GitHub и Resend не изменено. Всё ниже выполняете вы, по шагам, когда решите.
> Публичная регистрация (`PRIME_REGISTRATION=public`) включается **последним** шагом и только после юридической проверки документов ([PRIME_LEGAL_REVIEW.md](PRIME_LEGAL_REVIEW.md)).

Команды с `$` выполняются **на сервере** по SSH (без самого `$`), остальные — на Mac.

## Что нового

| Часть | Что делает |
|---|---|
| Возраст | одно нейтральное поле «Возраст» в той же форме (без отдельного экрана). Младше 13 — нельзя. 13–17 — только там, где возраст самостоятельной регистрации подтверждён (`PRIME_AGE_RULES`), иначе «нужно согласие родителя — пока недоступно». Страна спрашивается **только** когда от неё зависит ответ (при настройках по умолчанию — никогда). Хранится группа «13-17»/«18+» и страна, если её спросили. Проверяет **сервер**. |
| Документы | Пользовательское соглашение (галочка), отдельное согласие на обработку ПД (галочка), политика конфиденциальности (уведомление), информация для родителей. RU/EN, страницы сайта `/legal/<ru\|en>/<doc>.html`, открываются и внутри игры. |
| Запись согласий | коллекция `consents`: аккаунт, документ, версия, язык, время, способ. Регистрация без актуальных галочек отклоняется сервером. Старые аккаунты один раз принимают документы при следующем входе — прогресс, пароль и аккаунт сохраняются; до принятия PRIME CLOUD не пишет (выгрузка и удаление работают). |
| Защита регистрации | одноразовая проверка proof-of-work (без сторонних сервисов, ~1 с на телефоне), скрытое поле-ловушка, лимиты по IP (PocketBase), лимиты писем: 1 в минуту и 6 в сутки на адрес, дневной лимит сервера (`PRIME_MAIL_DAILY_CAP`, 90). Вход: 10 неверных паролей за 15 минут на один адрес → пауза (одинаково для несуществующих адресов). |
| Письма | письма RU+EN со ссылкой на политику; «Отправить ещё раз» с таймером; подсказка про «Спам». |
| Мои данные | PRIME ID → «Мои данные»: скачать JSON со всем, что сервер хранит об аккаунте; удалить аккаунт (пароль + галочка). Удаление — одна транзакция: аккаунт, профиль, сохранение, история, сессия, согласия. |
| Без отката прогресса | игрок не может вернуть старую версию облачного сохранения (маршрут восстановления отвечает 403; история остаётся для организатора через панель); гостевая карьера переносится только в аккаунт **без** облачного прогресса — на попытку переноса поверх сервер отвечает «conflict». Синхронизация PRIME CLOUD не менялась. |
| Удалённые не возвращаются | id удалённого аккаунта (без почты/ника) 60 дней хранится вне базы (`/var/lib/primetime/prime-deletions.log`). Если сервер восстановят из старой копии, при запуске такие аккаунты удаляются снова. |
| Очистка | раз в час: старые счётчики, просроченные проверки; регистрации 1.8.4 без подтверждения email старше 7 дней (`PRIME_UNVERIFIED_DAYS`). Аккаунты, созданные до 1.8.4, очистка не трогает. |
| Журналы и копии | журнал запросов PocketBase — 7 дней; в резервные копии больше не попадает (`auxiliary.db` не копируется); журнал доступа Caddy отключён (он хранил IP без срока). |
| Публичная без почты не откроется | `PRIME_REGISTRATION=public` без `PRIME_MAIL_MODE=smtp` → регистрация остаётся закрытой, в журнале предупреждение. |
| HTTPS | игра на `primetimeshowdown.online`, открытая по `http://`, сама переходит на `https://` (основной переключатель — «Enforce HTTPS» в GitHub Pages). |

Миграция `1792600000_prime_public.js` только **добавляет**: три коллекции (`consents`, `prime_limits`, `prime_challenges`), письма RU+EN, лимиты новых маршрутов, срок журнала 7 дней. Существующие аккаунты, профили, сохранения, история, сессии и приглашения не изменяются (проверено обновлением базы 1.8.3.1 → 1.8.4 в `npm run public:test`).

## Порядок развёртывания

### 0. До всего (ваши аккаунты и DNS)

1. **Resend** (панель):
   - ключ API, который стоит на сервере как SMTP-пароль, — с правами **только на отправку** (Sending access) и только для домена `primetimeshowdown.online`;
   - у домена выключено отслеживание **открытий и переходов** (иначе ссылки с токенами пойдут через сервер Resend);
   - посмотрите дневной лимит своего тарифа и поставьте `PRIME_MAIL_DAILY_CAP` ниже него (шаг 3).
2. **DNS** (панель Timeweb). Проверено чтением публичных записей 20.10.2026: SPF для `send.` и DKIM `resend._domainkey` есть, **DMARC нет**. Добавьте TXT-запись:
   ```
   _dmarc.primetimeshowdown.online   TXT   "v=DMARC1; p=none; rua=mailto:primetimeshowdown.official@gmail.com"
   ```
   Через 2–4 недели без проблем можно ужесточить до `p=quarantine`.
3. **GitHub** → репозиторий → Settings → Pages → **Enforce HTTPS** (сейчас `http://primetimeshowdown.online` отвечает без перехода на https).
4. Двухфакторная защита на GitHub, Timeweb, Resend, Gmail и DuckDNS.

### 1. Игра (GitHub Pages) — первой

Новая игра работает и со старым сервером (1.8.3): галочки и возраст старый сервер просто не читает. Поэтому сначала публикуется игра.

```bash
npm run publish:sync -- "/Users/user/Desktop/PRIME TIME SHOWDOWN"
```

Посмотрите список, затем то же с `--apply`, коммит и push в VS Code. В публикацию попадут и неопубликованные изменения 1.8.3.1 и CORS-документация.

Проверка: https://primetimeshowdown.online/legal/ru/privacy.html открывается; в игре PRIME ID → ссылки «Соглашение · Конфиденциальность · Согласие · Родителям» и RU/EN.

### 2. Сервер — обновление кода

```bash
npm run server:bundle
```

Скопируйте архив на сервер так же, как при обновлении 1.8.3 ([PRIME_CLOUD_2_DEPLOY.md](PRIME_CLOUD_2_DEPLOY.md)), и:

```bash
$ sudo /opt/primetime/deploy/update.sh
```

`update.sh` сам делает резервную копию перед обновлением, ставит новые хуки, миграцию и страницы, перезапускает PocketBase и при неудаче возвращает прежние файлы.

Проверка:

```bash
$ sudo /opt/primetime/deploy/healthcheck.sh primetime-showdown-beta.duckdns.org
$ sudo journalctl -u pocketbase -n 30 --no-pager | grep PRIME
```

Ожидается строка `PRIME: registration invite_only, email smtp, proof of work 18 bits` и в healthcheck «1.8.4: регистрация с проверкой…», документы открываются.

Регистрация остаётся `invite_only`: друзья при следующем входе один раз увидят «Документы PRIME ID» (возраст и две галочки) — прогресс сохраняется.

### 3. Сервер — настройки 1.8.4 (необязательно, значения по умолчанию безопасны)

```bash
$ sudo cp -p /etc/primetime/pocketbase.env /etc/primetime/pocketbase.env.before-1.8.4
$ sudo nano /etc/primetime/pocketbase.env
```

Можно добавить (пустая строка = значение по умолчанию):

```
PRIME_MAIL_DAILY_CAP=90
PRIME_POW_BITS=
PRIME_UNVERIFIED_DAYS=
PRIME_AGE_RULES=
PRIME_CLOSED_COUNTRIES=
```

`PRIME_AGE_RULES` — **только** возрасты, подтверждённые юристом (формат `US:13,GB:13`). Пока строка пуста, 13–17 не регистрируются нигде и страну никто не спрашивает. Как только правила появятся, форма сама начнёт спрашивать страну у 13–17-летних (а при `PRIME_CLOSED_COUNTRIES` или возрасте выше 18 — у всех).

Не трогайте `PB_ENCRYPTION_KEY`: им зашифрованы настройки в базе, простая замена сделает их нечитаемыми. Признаков компрометации ключа при подготовке 1.8.4 не обнаружено.

```bash
$ sudo systemctl restart pocketbase
```

### 4. Caddy — журнал доступа

`update.sh` Caddyfile не обновляет. Чтобы перестать хранить IP посетителей в журнале Caddy без срока:

```bash
$ sudo cp -p /etc/caddy/Caddyfile /etc/caddy/Caddyfile.before-1.8.4
$ sudo nano /etc/caddy/Caddyfile
```

Удалите блок `log { … }` (в проекте он уже убран: `deploy/linux/Caddyfile`), затем:

```bash
$ sudo caddy validate --config /etc/caddy/Caddyfile
$ sudo systemctl reload caddy
$ sudo rm -f /var/log/caddy/primetime-access.log*
```

Последняя команда удаляет старые журналы с IP-адресами — сделайте её, только если они не нужны для расследования.

### 5. Публичная регистрация — отдельным решением

Когда закрыты блокирующие юридические вопросы из [PRIME_LEGAL_REVIEW.md](PRIME_LEGAL_REVIEW.md) (тексты документов уже релизные, версия 2, но юридически не одобрены), игра 1.8.4 опубликована и шаги 0–4 сделаны:

```bash
$ sudo nano /etc/primetime/pocketbase.env      # PRIME_REGISTRATION=public
$ sudo systemctl restart pocketbase
$ sudo journalctl -u pocketbase -n 20 --no-pager | grep PRIME
```

Ожидается `PRIME: registration public, email smtp, …`. Если там `registration disabled` и `PRIME WARNING … needs email` — почта не включена, регистрация закрыта (так задумано).

Проверка с телефона: регистрация нового тестового адреса → письмо (и папка «Спам») → подтверждение → облако → «Мои данные» → удаление тестового аккаунта.

## Откат

| Что | Как |
|---|---|
| Публичная регистрация | `PRIME_REGISTRATION=invite_only` (или `disabled`) → `sudo systemctl restart pocketbase`. Данные не меняются. |
| Настройки 1.8.4 | `sudo cp -p /etc/primetime/pocketbase.env.before-1.8.4 /etc/primetime/pocketbase.env` → restart. |
| Код сервера | файлы предыдущей версии лежат в `/opt/primetime/pb_hooks.previous` и т. п. (их кладёт `update.sh`); вернуть их и перезапустить. Таблицы 1.8.4 старому коду не мешают — их можно не удалять. |
| База | только если миграция повредила данные: `sudo /opt/primetime/deploy/restore.sh <копия, сделанная update.sh>`. Аккаунты, удалённые после этой копии, сервер удалит снова при запуске. |
| Caddy | `sudo cp -p /etc/caddy/Caddyfile.before-1.8.4 /etc/caddy/Caddyfile && sudo systemctl reload caddy` |
| Игра | откатить коммит в репозитории публикации (GitHub Actions соберёт прежнюю версию). |

После `restore.sh` на сервере остаётся отложенная копия `pb_data.before-restore-…` с персональными данными — удалите её, когда убедитесь, что всё работает (скрипт напоминает).
