# DAILY PRIME STREAK — «Ежедневный эфир» (Alpha 1.8.9)

> **Статус (25.10.2026): готово локально, не опубликовано и не развёрнуто.** Сервер production и staging, базы игроков, Robokassa, документы и GitHub не менялись. Версия игры не повышалась (решение — отдельно).

## Что получает игрок

Одна награда в долларах за каждый игровой день, когда игрок забрал подарок. Серия растёт день за днём и не заканчивается после 7 или 100 дней.

| День серии | Награда | Что это |
|---|---|---|
| 1 / 2 / 3 / 4 / 5 / 6 недели | $75 / $100 / $125 / $100 / $150 / $125 | гонорар, утренний эфир, бонус спонсора, дневной эфир, повышенный гонорар, вечерний эфир |
| 7-й день каждой недели | $250 | еженедельный подарок |
| **7** | **$400** | «7 ДНЕЙ В ЭФИРЕ!» — первый рубеж |
| **14** | **$600** | «ДВЕ НЕДЕЛИ В ЭФИРЕ!» |
| **30** | **$1 000** | «МЕСЯЦ В ПРАЙМ-ТАЙМЕ!» |
| **60** | **$1 500** | «60 ДНЕЙ — ЗОЛОТОЙ СЕЗОН!» |
| **100** | **$2 500** | «100 ДНЕЙ В ЭФИРЕ — ЛЕГЕНДА!» |
| после 100 | обычная неделя, каждые 100 дней (200, 300 …) — юбилей $2 500 | серия продолжается |

Все суммы и правила — в одном месте: `src/config/daily.config.ts`. Сервер получает их через `npm run backend:rules` (`backend/pb_hooks/lib/daily_rules.js`); `npm run daily` падает, если файлы разошлись.

### Почему такие суммы

Обычная победа на «Новичке» ≈ $426 (KO, рейтинг 72, 2 комбо). Контракты бойцов стоят $500–1 800 ($6 000 всего), 15 карт магазина — $250–750 ($6 850). К тому же и контракты, и карты требуют уровня продюсера.

* Неделя визитов — $1 075: около 2,5 побед, примерно один контракт; меньше 25 % стоимости всех бойцов и меньше 25 % всех карт.
* Первые 30 дней — $5 275: меньше половины всего, что можно купить.
* Обычный день — меньше половины победы. Еженедельный подарок — меньше одной победы. Рубежи — от одной победы (7 дней) до шести (100 дней).

Ежедневные награды помогают, но карьера остаётся основным источником денег. Проверки баланса — в `npm run daily`.

## Как работает серия

* **Игровой день** — календарный день по Москве (UTC+3, без перехода на летнее время), по часам сервера, а не устройства.
* Один день — одна награда. Повторное нажатие, перезагрузка или другое устройство в тот же день → «уже получено».
* **Защита серии.** Один пропущенный день прощается бесплатно, но не чаще одного раза за 7 календарных дней. Пропущенный день не даёт награды и не увеличивает счётчик — серия просто продолжается при следующем входе. Если пропущено два дня подряд или защита ещё перезаряжается, серия начинается с первого дня. Рекорд, все выданные доллары и достигнутые рубежи сохраняются.
* **Рубежи** запоминаются навсегда с днём первого достижения. При новой серии деньги за рубеж выдаются снова, но новым достижением это не считается.

## Безопасность и PRIME CLOUD

Доллары в PRIME TIME: SHOWDOWN — часть сохранения, которое загружает игра; сервер проверяет только его формат (`lib/validate.js`). Поэтому ежедневная награда **начисляется самим сервером прямо в облачное сохранение**:

1. Игра сначала отправляет свой несохранённый прогресс (обычная синхронизация).
2. `POST /api/prime/daily/claim` передаёт только `{ op, base, session }` — идентификатор запроса, ревизию облачного сохранения, с которой игра синхронизирована, и игровую сессию.
3. Сервер в **одной транзакции**:
   * проверяет подтверждённый email, принятые документы и активную игровую сессию (PRIME CLOUD 2.0);
   * определяет игровой день по своим часам, день серии и сумму по таблице;
   * добавляет сумму в `money` облачного сохранения и ставит отметку `daily = { claims, day }`;
   * сохраняет новую ревизию (предыдущая уходит в историю с причиной `daily`);
   * обновляет `daily_streaks` и записывает `daily_claims`.
4. Игра применяет то же изменение к своей копии. Тексты совпадают побайтно (канонический JSON с обеих сторон), поэтому нет ни перезагрузки, ни конфликта.

Защиты:

* Уникальные индексы `(owner, day)` и `(owner, op)` исключают двойную выплату, даже если запросы пришли одновременно с двух устройств.
* Если ответ потерялся, повтор запроса с тем же `op` возвращает ту же выплату, ничего не начисляя повторно.
* Неотвеченная заявка хранится в метаданных синхронизации и отправляется повторно перед любой следующей загрузкой.
* Отметка `daily.claims` в сохранении не даёт применить одну и ту же выплату дважды.
* Гостю награды не начисляются: окно предлагает войти в PRIME ID.

Ограничение, которое остаётся (оно не связано с этой функцией): сервер по-прежнему не проверяет, откуда взялись доллары в загружаемом сохранении. Подделать деньги в сохранении можно было и раньше. Ежедневная награда эту дыру не расширяет: её нельзя выбрать, повторить или пересчитать со стороны браузера.

## Серверные компоненты

| Файл | Что делает |
|---|---|
| `backend/pb_migrations/1793000000_prime_daily.js` | коллекции `daily_streaks` и `daily_claims` (без доступа через общий API, каскадное удаление вместе с аккаунтом), уникальные индексы, лимит запросов `/api/prime/daily` (30 в минуту); откат удаляет только их |
| `backend/pb_hooks/lib/daily.js` | правила (чистые функции, общие с Node-тестами) и обработчики `GET /api/prime/daily`, `POST /api/prime/daily/claim`; выгрузка для «Мои данные» |
| `backend/pb_hooks/lib/daily_rules.js` | таблица наград (генерируется) |
| `backend/pb_hooks/prime.pb.js` | маршруты |
| `lib/prime.js` | `daily: 1` в `/api/prime/config`; экспорт проверок сессии и записи сохранения |
| `lib/validate.js` | принимает поле `daily` в сохранении |
| `lib/account.js` | `daily` в выгрузке «Мои данные» |

Переключатель `PRIME_DAILY=off` в окружении сервера выключает функцию: игра не показывает подарок. По умолчанию функция включена.

Тестовые часы: `PRIME_DAILY_CLOCK_FILE` читается **только** при `PRIME_SERVER_ROLE=dev`. Production и staging их никогда не читают; это проверяется в `npm run daily`.

## Интерфейс

* **Подарок** — в главном меню, в правой колонке под кнопкой звука (42×42, тот же отступ). Он не задевает верхнюю строку, логотип и кнопки меню. Подарок показывается, только если сервер поддерживает серию.
* **Индикатор:** золотая точка, пока подарок ждёт, и мягкая пульсация три раза, после чего тишина. Когда награда забрана, индикатор исчезает.
* **Разовая подсказка** «ТВОЙ ЕЖЕДНЕВНЫЙ ЭФИР НАЧАЛСЯ!» появляется у аккаунта, который ещё ни разу не забирал награду. Она исчезает после открытия окна или нажатия «×»; хранится только локальная отметка.
* **Окно** (`src/ui/dailyUI.ts`):
  * серия, рекорд, статус «сегодня»;
  * главный подарок (сегодняшний или завтрашний);
  * лента из 7 дней: последние полученные и ближайшие;
  * дорожка рубежей 7 / 14 / 30 / 60 / 100 с прогрессом;
  * кнопка «ЗАБРАТЬ НАГРАДУ» или «ПОЛУЧЕНО» с отсчётом до следующего игрового дня;
  * состояние защиты серии.

  Для гостя, неподтверждённого аккаунта, непринятых документов и подключения PRIME CLOUD — отдельные понятные состояния.
* **Вручение** начинается только после ответа сервера:
  * обычный день: подарок, лучи, искры, подсчёт суммы;
  * рубеж: золотой фон, конфетти, заголовок рубежа;
  * короткие CSS-анимации и синтезированные звуки игры (`confirm` / `level` / `coin`).

  При `prefers-reduced-motion` или игровой настройке «Движение камеры: без тряски» вручение спокойное: без лучей и частиц, сумма показывается сразу. При ошибке — сообщение без ложной сцены вручения.

## Проверки

`npm run daily` — 71 проверка: правила, баланс, сохранение и реальный PocketBase во временной базе с тестовыми часами. Сценарии: гости и неподтверждённые аккаунты, первая награда, тот же день, подделанный запрос, повтор запроса, три параллельных запроса, два устройства, пропуск с защитой, повторный пропуск, 106 дней подряд с рубежами и продолжением после 100, потеря ответа и потеря запроса, «Мои данные», удаление аккаунта, выключатель, игнорирование тестовых часов на production.

## Развёртывание (по отдельному решению владельца)

1. Повысить версию до 1.8.9 и собрать серверный архив (`npm run server:bundle`).
2. Сначала staging, затем production: обновление через `update.sh` применит миграцию `1793000000_prime_daily.js`.
3. Сайт выпускать после сервера. До обновления сервера сайт 1.8.9 просто не покажет подарок (`daily` отсутствует в config).
